# OA 组织、权限与审批元模型（Demo）

“元模型”是系统的语义和控制规范：它规定对象类型、关系类型、事件、状态机、数据策略和发布治理；业务模型、系统映射和实际数据实例都必须遵循该规范。

本 Demo 首先构建 `OA-META-001`，覆盖：组织、人员、岗位、业务角色、审批流、审批节点、审批实例、待办任务、业务动作和审计记录。

## 业务人员可视化建模

业务人员不需要编写代码。工作台提供业务对象库、对象画布、字段属性面板和关系编辑器：可添加“采购需求”“质量复核”“预算校验”等对象，用业务语言描述关系，并填写业务主键、字段与数据分级。

生产、质量、采购和市场负责人可作为“业务建模协作人”保存和校验草稿；管理层保留版本发布权。权限中心应在生产环境进一步按组织和数据域配置该能力。

## 模拟构建流程

1. 在独立语义运营端进入“模型校对”，或在管理 Web 的独立语义模块中打开“OA 组织、权限与审批元模型”。
2. 由业务建模协作人可视化编辑对象、字段和关系，先保存草稿并执行校验。
3. 校验通过后点击“模拟构建 OA 元模型”，平台生成受控的模拟实例及关系。
4. 只有管理层可发布通过校验和模拟验证的版本。

模拟不读取或写入真实 OA。生产落地时应把 `oa.*` 映射替换为实际 OA/BPM 的 API、Webhook 或 CDC 连接器，并采用账号中心、权限中心与密钥中心签发的短时凭据。

## 与智脑的关系

智脑发起采购等业务时，先通过元模型定位用户的组织、角色、业务动作和审批流；只有“角色具备能力 + 数据域允许 + 审批实例状态满足条件”才可进入下一步。元模型因此成为智脑受限访问与受限发起业务的共同依据。
