# 元域智脑学习与数据使用控制面

## 已实现边界

智脑当前不会把普通对话自动写入长期记忆，也不会使用企业业务数据训练基础模型。长期目标只有在用户点击“固定为长期记忆”后才保存，默认保留 90 天，用户可以随时删除。

“成功工作流学习”默认关闭。用户明确开启后，只有同时满足以下条件的结果才形成候选信号：

1. 动作来自服务端允许列表；
2. 动作经过当前用户的一次性确认；
3. 业务工具或桌面端返回成功回执；
4. 回执仍绑定原租户、用户、会话、设备和 Run。

候选信号只记录角色、工具 ID、结果类型、Run 指纹和成功次数，不保存原始提问、模型上下文、文件正文、企业系统返回载荷、绝对路径或 URL 查询参数。信号保留 30 天；关闭授权会立即清空当前用户的全部工作流学习信号，也可以逐条撤销。

候选信号只有在同一受控工作流累计 3 次已确认成功、个人化开关保持开启且用户没有给出负反馈时，才成为排序建议。用户可将建议标记为有用或无用；无用会立即抑制该信号。推荐只改变展示和工作流排序，不能跳过权限、一次性确认或审批。

## 数据用途分层

| 数据 | 当前用途 | 是否进入模型训练 | 用户控制 |
| --- | --- | --- | --- |
| 当前任务对话 | 任务内上下文与审计 | 否 | 可归档任务 |
| 主动固定的目标 | 跨任务目标承接 | 否 | 可逐条删除 |
| 企业 OA/ERP/WMS 等数据 | 当前权限内检索与证据生成 | 否 | 随权限实时裁剪 |
| 成功工作流信号 | 后续工作流排序和推荐的候选依据 | 否 | 默认关闭、可关闭清空、可逐条撤销 |
| 原始提问与企业载荷 | 不进入学习信号 | 否 | 不采集 |

## 控制接口

- `GET /api/agent/learning-profile`：查看个人授权、信号数量、最小化信号和固定数据策略。
- `POST /api/agent/learning-profile`：以乐观锁版本更新 `workflowLearningEnabled` 或 `personalizationEnabled`。
- `DELETE /api/agent/learning-signals/{id}`：撤销当前用户的一条工作流学习信号。
- `POST /api/agent/learning-signals/{id}/feedback`：提交 `{ "helpful": true|false }`，用于强化或抑制个人建议。

设置接口拒绝未知字段，不能通过客户端开启原始提问训练或企业载荷训练。企业知识模式固定为 `retrieval_only`，模型训练模式固定为 `disabled_without_approved_dataset`。

## PostgreSQL 共享控制面

学习授权和最小化成功信号可通过独立开关迁移到共享 PostgreSQL：

```powershell
$env:AGENT_LEARNING_STORE_DRIVER='postgres'
$env:RUNTIME_POSTGRES_URL='postgresql://user:password@db.example.internal/agent?sslmode=verify-full'
```

PostgreSQL 模式把个人授权 Profile 和成功信号作为同一个数据库事务处理：记录信号时在行锁内重新确认授权仍然开启；关闭授权时，Profile 变更和个人信号清空同事务提交。因此另一个 API 节点不能在用户撤回授权后继续写入信号。版本冲突、跨主体查询、过期清理和逐条撤销继续失败关闭。API 就绪探针会报告 `agentLearningStore` 的实际 driver 和连接状态。

当前没有 SQLite 学习 Profile/信号的自动搬迁程序。灰度切流需要停止写入并核对授权版本、主体数量、信号数量、过期时间和撤回结果；不得同时把两个存储作为权威来源。

## 后续生产化

下一步不是直接“拿公司数据微调”，而是先建设经批准的数据集管线：数据分类、脱敏、合法用途登记、人工验收集、版本化、隔离训练环境、可回滚发布与持续评测。只有完成组织级审批后，才能增加新的训练用途；个人工作台开关不能越过该审批边界。PostgreSQL 共享存储只解决授权和候选信号的一致性，不代表已经获得模型训练授权。
