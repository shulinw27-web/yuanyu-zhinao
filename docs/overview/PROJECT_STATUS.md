跳过（那是刻意的：`UNASSIGNED` 的含义是「来源未知」）、4a 字段目录不含这两个对象、跨系统标识对应 **0 条**、Critic 报「受控来源系统：存在未登记来源系统」、采纳被 `SEMANTIC_PROPOSAL_CRITIC_FAILED` 拒绝。**卡住整条链路的信息一直就在材料里**——两条抽取路径（结构化字典 vs **模型只提供归属原文，系统码由服务端确定性判定**——契约里**没有「系统码」字段**，模型不能直接写 `ERP`；它给的是「材料里哪句话说明了这张表属于哪一处」（`systemEvidence`，与 `evidence` 同严格度：必须在材料里逐字出现，否则整表拒绝 `OWNER_EVIDENCE_INVALID`），服务端用系统注册表（ADR-009）的 `detectDeclaredSystemCodes` 判定。理由两层——**安全**（让模型直接输出系统码就是给它一个无法复核的断言入口）与**事实源**（系统码与别名的定义已在注册表，不必在抽取层再养一份）；粒度也因此落到**表级**：整篇材料会同时提到多个系统，只有把判定收窄到模型引用的那一句才能回答「哪张表属于哪个」。(2) **判定结果一律是候选，绝不写 `sourceSystems`**（写入 `candidateSourceSystems` + `candidateSourceBasis: 'material_owner_evidence'` + `candidateSourceEvidence`）——`sourceSystems` 在本系统里是**事实**（受控系统目录与范围裁剪都读它），推断不得冒充事实，与 ADR-014 决策 1、ADR-016 决策 3 是同一条纪律。(3) **候选不参与范围裁剪——本 ADR 最重要的一条**：范围过滤只看已确认的 `sourceSystems`，候选归属在范围内或在范围外都**不影响对象去留**，只进 `candidateScopeObjects.inScope / outOfScope / unregistered` 上报。若让候选参与裁剪，模型在材料里「引用」一句归属于范围外的原文就能把一个对象从提案里删掉，而人对这句话还没有任何确认动作；ADR-013 要求「被排除项必须显式列出」的前提是**排除的依据是事实**。(4) **候选可以进 4a 字段目录**（新增第三个 grounding `material_owner_candidate`，进入条件是「有候选归属且候选系统在本次所选范围内」）——不进则非结构化材料路径的跨系统对应**永远为 0 条**，阶段 4 第 2 条完全落空；进了也只是**候选链接**，仍要过 4b 逐条确认与 4c 等价裁定两道关口，模型无从「直接写入」。(5) **候选转事实走人工确认**（复用既有复核动作 `PATCH .../proposal` 新增 `sourceAssignments: { objectId, system, evidence }`）：**依据不得为空**（归属是参与裁剪的事实，写入它必须留下依据，「人点了一下」不是依据）、目标系统必须已在系统注册表、集合是**全量语义**（省略＝不调整、空数组＝撤销全部、显式提交一个无候选归属的对象＝硬错误）、确认后才写入 `sourceSystems` 并**这时才**按范围重新裁剪；**撤销是双向的**——回退到原稿来源时，此前因范围被裁掉的对象与关系要按**原稿顺序**排回，否则「撤销」会静默丢掉一部分原稿。(6) **零 / 多 / 识别不到三类分别上报，一律不猜**：识别出恰好一个已登记系统才产出候选；识别出多个 → `ambiguous`（含全部候选码与原文）；一个都识别不出或只识别到未登记系统名 → `unattributed`（含原文）。多候选时「选哪个都对」需要域知识，服务端不做；识别不到时不猜一个最近的系统。**三处靠实测修正的地方**：① **归属判定不能用业务词别名**——`detectSystemCodesInText`（`semantic-source-discovery-service.js` 里供「文本提到什么系统」用）的别名含「采购 / 库存 / 供应商」，用于**归属**会把一句「采购订单表」判成 ERP 所有权，故另设 `detectDeclaredSystemCodes`，**只认系统码与系统名**；② **候选不能与 confirmed 来源抢占目录**——候选仅在对象**无 confirmed 来源**时才进目录，否则同一对象会因两处字段集不同凭空产生一条 `declaration_divergence`，那是**虚假冲突**；③ **归属确认必须先于标识重算**——顺序反了会让刚确认的归属在本次请求里还没生效，运营点了确认却看不到对应出现（三个关口的顺序依赖：**归属 → 等价裁定 → 对应确认**）。**验收（本机实测，注入模型输出的确定性用例，6 系统，未跑真实模型轮次）**：`npm run quality` 端到端 **EXIT=0**（1m58s，全文 **0 处 `not ok`**，链尾 本次整理的验证结果在 [整理记录](REPOSITORY_CLEANUP.md) 单独记录；未重新执行的企业级测试不计入此次结果。
