# 项目交接

更新：2026-09-03。适用于当前开发目录，不代表生产验收。

## 项目要解决什么

元域智脑分为三类入口：员工使用智脑工作台提出业务和日常工作诉求；运营人员使用独立语义 Agent 构建与校对语义模型；管理人员通过元域智营维护权限、配置并查看运行情况。语义层负责统一对象、关系和来源，业务授权始终由服务端决定。

## 接手时先做什么

1. 阅读 [当前状态](PROJECT_STATUS.md)，区分开发基线、Mock 能力与外部待验收事项。
2. 按 [开发指南](../development/GETTING_STARTED.md) 启动 API 及所需客户端，不要同时启动两个争用同一端口的实例。
3. 运行 `npm run docs:check` 和 `npm run quality`，记录测试环境与结果。
4. 修改具体能力前查 [模块索引](../modules/CODEX_INDEX.md) 和对应 API，不从历史交付记录推断接口。
5. 开始真实数据联调前准备 [系统接入材料](../development/DEVELOPMENT_READINESS.md)，上线条件见 [生产 Checklist](../operations/PRODUCTION_TODO_CHECKLIST.md)。

## 不能破坏的约束

- 业务智脑和元域智语 Agent 是不同入口与授权场景，不能用运营权限替代业务权限。
- 无业务意图的聊天不自动发起业务操作；写入必须经过对应确认、审批与执行校验。
- 用户、租户、角色、设备和任务上下文需要隔离；记忆不是权限，也不是长期执行授权。
- 客户端与模型不能取得企业系统原始凭据，不能直接写企业系统。
- Semantica 的结构建议需要人工校对；语义模型不能自行绕过发布治理。
- 本地工具只在受控范围内执行；“已生成建议”“已排队”“已写入文件”必须区分。
- 学习信号采集需要用户授权，不能描述成已自动训练模型权重。
