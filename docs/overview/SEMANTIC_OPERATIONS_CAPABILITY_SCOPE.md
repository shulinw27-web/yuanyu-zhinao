## 1. 产品定位

身份与权限补充（2026-09-08）：元域智语 SDK 已支持选择企业 OIDC 身份源，并与智脑共用服务端身份适配及 IAM 校验。获得业务登录资格不等于获得建模或发布权限。专用平台的运营宿主免登仍需独立接入，见 [身份源适配指南](../guides/IDENTITY_PROVIDER_ADAPTERS.md)。

元域智语端负责把业务概念和数据结构整理成可审阅、可校验、可版本化的语义模型。用户可以先用自然语言讨论业务，再根据数据字典形成候选对象与关系，经过人工校对和治理流程后交给 Semantica 校验与登记。

它服务于语义层建设和运营，不负责采购下单、库存调整、业务审批或员工日常办公。建立语义模型也不等于建立真实 ERP 连接，更不等于获得企业数据访问权限。

当前形态为独立 Web 端及 Electron 桌面端，主要工作区为“Agent 工作台”“模型校对”“版本与回滚”。

| 连续对话 | 承接前文数据字典、字段追问、目标补充和提案后的继续讨论 | 已实现；仅限身份可见的有限历史，不是无限记忆 |
| 自然语言生成候选 | 从明确业务描述提取对象、字段、主键、引用和关系，生成待审阅提案 | 有条件；原文证据不足不能用模型猜测补成正式定义 |
| 结构化字典识别 | 解析受支持的 JSON、YAML、CSV 数据字典及 OpenAPI Schema | 已实现；依赖受支持格式和安全准入，不支持任意文件结构自动识别 |
| 来源预检 | 查看已登记系统目录、连接状态、候选对象及接入缺项 | 已实现；不等于扫描企业网络、发现所有数据库或读取业务明细 |
| 可视化人工校对 | 对象关系图、节点与字段联动、主键、来源、类型、映射、基数编辑 | 已实现；所有编辑仍需服务端校验和对应权限 |
| 模型治理补充 | 在模型校对中维护指标、术语、数据契约、质量规则、访问策略和血缘等定义 | 已有结构维护入口；不等于所有规则都已在真实业务系统自动执行 |
| 自动结构检查 | 检查对象唯一性、主键、来源、关系闭合、核心锚点和字段映射 | 已实现；结构合法不代表业务语义正确 |
| 样本映射演练 | 在本机 Mock 样本上检查字段转换、命中和阻断问题 | 已实现；无样本不能视为映射成功，不是全量数据对账 |
| Semantica 集成 | 读取受控候选结构，验证模型定义，执行受控模拟和登记路径 | 有条件；需要独立服务与有效材料，不能只看页面模板判断服务可用 |
| 版本与回滚 | Agent 采纳和有语义变化的手动保存均留快照，展示操作者、时间、来源、Diff 和回滚记录；按当前草稿指纹启用安全回滚 | 已实现；版本数无固定上限；只回滚未发布草稿，不撤销已发布版本或外部业务数据 |
| 任务与审计 | 多任务切换、查询、状态筛选、归档、提案修订、确认和证据时间线 | 已实现；权限不足和失败必须可见，不得伪装完成 |
| 只读巡检 | 检查来源就绪、结构完整性、部署差异和映射覆盖，形成独立通知；与模型审核工作台待办分区展示 | 有条件；需巡检 Worker，默认入口为每日巡检；立即巡检按钮仅触发到期，不自动修复或发布 |
| 桌面报告导出 | 导出受支持的语义任务报告并提供本机查看入口 | 仅 Electron 对应导出能力；不是通用电脑控制工具 |

## 3. 建模输入与输出

### 用户应提供的材料

至少说明要覆盖的业务过程、对象和字段。要形成可用模型，还应补充：来源系统及表/接口名称、稳定主键、外键指向、关系基数、字段类型、单位和枚举、敏感等级、指标口径，以及可用于核验的脱敏样本。

自然语言描述可以作为开始，但不能替代缺失的业务事实。例如“订单可以多次入库”可以提出一对多关系候选，不能由此自动推定库存扣减规则、金额分摊方式或所有异常处理流程。

### 材料支持范围

- JSON/YAML：支持项目已实现的数据字典结构；OpenAPI 主要从 `components.schemas` 提取对象与字段。
- CSV：支持按表、字段、类型等列组织的数据字典，不保证任意导出的 CSV 都能自动识别。
- PDF、DOCX、XLSX：可通过受控文本提取辅助理解，不等于完整还原页面、公式、图形与版式。
- JPEG、PNG、WEBP：存在附件准入与适配路径，实际视觉能力取决于模型、扫描和出网配置。

2026-09-07 多模态专项已验证上述格式的小型合成字典、表格、关系图及扫描/混合 PDF，含后续追问。Word 和关系图均生成两对象一关系的待校对候选，PK/FK 缩写可被引用；未完整读取或已隔离附件不生成完整候选。图片在独立合成测试进程中验证，实际 API 仍需企业扫描与图片出网审批才能启用。音视频和任意复杂材料不在通过范围，见 [专项报告](../development/AGENT_MULTIMODAL_ACCEPTANCE_2026-09-07.md)。结构化解析每次最多保留 40 个 Schema、每个最多 80 个字段；大字典需分批处理，检查“附件读取范围”中的截断和缺失提示。

### 系统应交付什么

候选提案包含对象编码、业务名称、字段与主键、来源、分类、核心锚点、关系方向与基数，并附结构检查、相对当前草稿的差异及映射演练结果。

自然语言未提供来源或类型时，可以形成待校对候选，但必须保留 `UNASSIGNED`、待确认映射或类型待复核等提示。默认显示 `string` 不表示模型已识别出正确类型；出现绿色结构项也不意味着可直接发布。

结构化提案、人工草稿、已登记模型和图中的事实是不同对象，不能把“生成提案”称作“语义层已建成”。

## 4. 人工校对与 Semantica 的关系

当前建设过程分为以下阶段：

1. 讨论目标并读取已准入的材料，或从受控来源目录、Semantica 图投影发现候选结构。
2. 形成候选对象与关系，核对原文字段和证据，不自动采纳。
3. 在可视化编辑器检查对象、主键、字段、来源系统、映射、关系方向和基数。
4. 查看结构检查、差异、影响及 Mock 样本映射结果，修正阻断问题。
5. 经授权确认后采纳到未发布草稿，保留修订及快照。
6. 草稿校验、模拟构建通过后，由有发布权限的身份确认登记；Semantica 不可用或定义校验失败时阻断。

Semantica 是模型定义校验与上下文图服务，不是替代人判断业务口径的另一个聊天机器人。返回运营端的主要是结构、来源、统计和受控关系证据，不直接开放原始业务记录。

当图中尚无事实时，页面可能展示平台契约模板；模板不是从公司真实数据中抽取的结果。图中观察到共同业务标识，也仍需要人工判断能否成为正式关系。

“服务在线”“图中有事实”“模型定义已登记”“草稿与已部署版本一致”必须分别检查。刷新服务状态不会执行模型发布。

## 5. 权限、确认与版本边界

| 操作 | 当前约束 |
| --- | --- |
| 咨询、字段追问 | 不应创建可执行写入命令，不因提到发布而认为用户授权发布 |
| 生成候选与采纳草稿 | 受建模/草稿权限约束；候选形成不等于采纳，未通过检查不能直接执行 |
| 校验及模拟 | 分别检查相应权限、目标版本和当前状态，不使用旧结果替代新版本检查 |
| 正式登记 | 必须具备发布权限，经过前置验证与明确确认；模型输出不能赋予权限 |
| 回滚 | 从版本界面选择明确快照，确认影响；存在后续改动时不能静默覆盖 |
| 来源及访问策略编辑 | 维护的是模型定义，不会自动配置连接器凭据或授予真实数据访问权 |

Agent 执行命令使用受控确认机制并记录证据。用户说“建立候选，但不要发布”应停在候选审阅；说“只讨论，不建模”只得到解释。具体界面按钮和可执行动作以服务器返回的当前身份权限为准。

当前回滚恢复的是未发布草稿，不会自动撤销 Semantica 已登记版本，不会回滚 ERP 数据、图中全部事实或数据库结构。

## 6. 会话、任务与日常运营

运营人员可以创建独立任务、在同一会话连续补充材料、筛选任务状态、查看证据并归档。生成提案后仍可以返回咨询，例如询问“这个外键为什么这样关联”。

模型理解只使用当前身份可见的有限历史和材料摘录；目前没有将业务智脑的“固定长期目标”机制等同开放为运营端的自动跨任务记忆。也不会通过积累字典聊天自动训练模型。

任务状态应按实际结果解释：已回应只是本轮有回答；等待补充表示信息不足；等待确认不代表校验通过；权限不足、阻断及模型失败均不能算执行完成。

只读巡检可以按现有检查项运行，支持暂停、恢复和立即检查，并展示通知。定时触发依赖独立 Worker，不能因为启用了计划就认为后台一定在持续运行；它不会自动补映射、变更权限或发布模型。

Electron 桌面端可使用受限语义报告导出；Web 页面和桌面壳不是完整同权的本机文件执行环境。运营端不继承智脑的六类电脑工具。

## 7. 当前不支持或不能承诺的事项

- 仅凭一句模糊需求就自动建成公司完整语义层，或省略业务人员对主键、口径和权限的确认。
- 自动扫描任意企业系统、获取凭据、修改数据库、配置生产连接器并完成数据接入。
- 把模板候选冒充实际观察结果，或把空样本校验说成数据转换成功。
- 不经审阅和权限检查直接采纳、发布、覆盖或删除模型。
- 任意长文档、复杂 Excel 公式、图片与音频都能完整理解。
- 自动撤销生产模型、跨系统回滚业务数据，或保证无停机模型迁移。
- 充当全公司通用运维 Agent，自动管理服务器、账户、告警和任意外部工具。
- 用运营材料自动训练基础模型，或让语义模型本身替代身份与数据权限控制。

## 8. 当前验收依据与使用前提

2026-09-07 双端核心真实方舟用例共 12/12 通过，其中元域智语为 4 项：能力问答、字典方案解释、主键追问、生成候选。双端附件续问共 4 项，元域智语占 2 项。完整项目 326 项自动回归包含相关权限、确认、任务及校验测试，不是运营端单独有 326 项。

本机真实 Semantica 引擎曾在该轮测试中导入 4 条合成事实，形成 11 个节点、24 条边，候选发现和模型定义校验通过；该轮没有执行正式发布。候选示例由于来源和映射待核实而被阻断，这是正确的安全结果，不是“建模全流程已发布成功”。

使用前需具备有效运营身份、对应权限、可用 API/模型、建模物料和需要时的 Semantica 服务；真实发布及定时巡检还分别依赖完整前置条件和 Worker。真实企业 Connector、组织字段权限、DLP、多模态和生产发布需另行验收。

当前方舟是云端模型，受控材料可能以脱敏上下文发送给模型服务；因此“元域智语独立端”不等于完全离线。真实敏感字典和文档应先核定数据分级与允许用途。

本次编写说明只核对已有代码与记录，没有重跑模型或发布测试。

## 9. 一个完整的试用例子

先提供：

```text
只讨论方案，不保存、不发布。
采购订单 po_header：po_no 为主键，supplier_code，amount。
入库单 receipt：receipt_no 为主键，po_no 引用采购订单，received_qty。
同一采购订单可以多次入库。请解释关系以及金额如何避免重复统计。
```

应得到订单到入库一对多的解释，并指出订单金额应按订单粒度统计，不能连接入库明细后直接重复求和。

随后问“采购订单主键是什么？”应回答 `po_no`；再说“根据这份字典生成候选，仅供审阅”，应展示 2 个对象及相应引用关系。因未提供来源、字段类型和样本，提案还需人工补齐，不应直接发布。
