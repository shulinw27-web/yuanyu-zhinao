# Demo 优化复盘：十个问题与完成项

> 历史阶段记录：保留验收与演进依据，不作为当前完成度或操作入口。当前状态见 [项目状态](../../overview/PROJECT_STATUS.md)。

| 问题 | 判断 | 已完成优化 |
| --- | --- | --- |
| 1. 五个核心元对象是否被系统正式识别？ | 是；Schema `1.1.0` 已增加门店。 | 建立 L0 核心元对象服务与 API，并将门店同步到 OMS、语义图和权限边界。 |
| 2. 流程是否必须关联核心对象？ | 采购已覆盖，其他动作未统一。 | 为采购、质量、市场、预算等动作增加统一核心对象策略。 |
| 3. 缺少对象时是否真正阻断执行？ | 需要统一控制点。 | 业务条线、智脑短时授权、核心元对象三项联合判定。 |
| 4. 业务人员能否安全地编辑元模型？ | 可以编辑，但对象编码曾可被误改。 | 对象编码改为稳定只读标识；新增对象使用受控入口。 |
| 5. 建模是否按业务语言表达？ | 需要降低技术门槛。 | 对象库、字段面板、关系编辑器、校验与发布链路已提供。 |
| 6. 谁可建模、谁可发布是否明确？ | 需要分离职责。 | 业务负责人可建模和校验；管理层保留发布权。 |
| 7. 人员对象是否与身份权限体系贯通？ | 必须贯通。 | 人员定义为 OA / 账号中心权威来源，承载责任、角色和审批身份。 |
| 8. 原材料、产品、设备、门店是否有权威来源与生命周期？ | 必须明确。 | 为四类业务对象定义多系统权威来源、主键、生命周期与治理边界；门店额外绑定组织归属。 |
| 9. 智脑的业务建议是否能解释其依据？ | 应提供可审计证据。 | 采购计划新增核心元对象校验步骤与绑定对象证据。 |
| 10. 变更是否经过端到端验证？ | 必须。 | 完成接口、规则、Web、桌面端和移动端构建验证。 |

## 当前执行门禁

`用户条线权限 ∩ 智脑短时工作流授权 ∩ 核心元对象绑定` 三项均通过，业务动作才可进入用户确认和审批。任一项失败，系统保留分析能力，但拒绝发起写入类流程。

## 后续生产化建议

将内存草稿、静态绑定和模拟实例替换为 PostgreSQL 版本库、事件总线、真实系统连接器和不可篡改审计仓；并为每个核心对象建立数据负责人、质量规则与变更审批策略。
