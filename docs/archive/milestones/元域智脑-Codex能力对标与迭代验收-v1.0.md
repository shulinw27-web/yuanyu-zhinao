## 1. 对标口径

本次以 Codex 的任务型 Agent 工作方式作为产品参考，而不是复制其开发工具能力。重点关注：可持续任务、上下文管理、并行任务空间、工具调用边界、长期记忆与验证闭环。

OpenAI 官方文档将多智能体协调、跨轮推理上下文、受控工具调用、评测和明确的人机审批边界列为长流程 Agent 的关键能力。元域智脑采用相同的设计原则，但所有业务数据访问和写入仍由企业服务端权限与审批规则决定，模型不直接获得系统写权限。

## 3. 本次架构结果

```text
用户身份
  │
  ├─ 多任务窗口（每个窗口一个持久任务）
  │     ├─ 目标 / 领域 / 阶段 / 运行 ID
  │     ├─ 会话上下文与压缩摘要
  │     └─ 确认、撤回、审批回执
  │
  ├─ 长期用户目标记忆（租户 + 用户 + 角色隔离）
  │     ├─ 自动安全写入或用户主动固定，90 天保留、过期清理、可删除
  │     ├─ 批次 / 物料 / 订单等实体仅作检索线索，不作为事实
  │     ├─ 仅用于理解和路由
  │     └─ 冲突时追问，不读取数据
  │
  ▼
任务合同：理解 → 授权 → 读取 → 分析 → 本人确认/审批
  │
  ▼
服务端策略、企业 Connector、受控工具、证据链
```

## 4. 三轮自问与修复

| 轮次 | 自问 | 风险 | 修复 | 验证 |
| --- | --- | --- | --- | --- |
| 1 | 多个长期任务下，“给我方案”会不会错误承接最新任务？ | 任务串域、错误读取数据 | 多领域长期目标冲突时进入选择状态，未选择前不检索、不执行 | 安全回归：冲突记忆返回 `needs_input`，证据为空 |
| 2 | 确认或撤回后关闭窗口，任务状态是否仍正确？ | 重开后可能误显示“待确认” | 执行、撤回回执写回持久任务窗口 | 会话回归：任务状态持久化为等待审批/已撤回 |
| 3 | 长会话压缩后，原始任务目标会不会被短追问覆盖？ | 上下文漂移、错误路由 | 将任务目标独立保存并优先于压缩摘要和短句 | 会话回归：压缩后仍保留批次报警目标 |
| 4 | 用户想长期追踪一个任务时，能否明确控制记忆内容和有效期？ | 隐式记忆不透明、旧目标干扰 | 增加“固定为长期记忆”、实体线索和 90 天自动清理 | 会话回归：固定目标包含 RM/PB 实体；越权固定被拒绝；过期项被清理 |

## 5. 验收结论

本次完成了从“多聊天窗口”到“多持久任务窗口”的升级，并使长期记忆进入受控闭环。智脑已经能：

1. 在同一任务中长期保持目标，即使上下文被压缩；
2. 在新任务中承接用户的最近长期目标；
3. 遇到多目标冲突时先澄清，不以猜测读取企业数据；
4. 在确认、撤回和草稿创建后保持正确任务状态；
5. 让用户查看和删除长期记忆。
6. 主动将当前任务固定为长期记忆，并看到关联的业务实体线索。

下一阶段应基于真实企业数据和业务人员验收样本，建立覆盖 OA、ERP、MES、WMS、QMS 的任务成功率、证据完整率、误路由率、无效追问率和确认前写入率评测集。
