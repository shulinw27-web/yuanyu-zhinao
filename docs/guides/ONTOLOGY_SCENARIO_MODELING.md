# 业务场景建模与质量判断使用指南

更新：2026-09-09。适用于元域智语 Web/Electron 与元域智营的模型校对工作台。

## 这次增加了什么

模型不再只有 OA 审批一种校验方式。`oa-approval` 保留原有必备审批对象和审批策略；`general` 允许小场景建模，包括一个对象、没有关系的独立场景。通用模式必须填写业务目标、验收问题和治理资产，不会因此获得数据访问或业务执行权限。

当前存储空间和接口仍沿用 `oa-governance`，是兼容现有客户端的名称，不代表通用模型必须包含 OA。此次没有迁移历史对象编号，也没有增加多模型独立存储空间。

## 从质量场景开始

1. 打开元域智语端的“模型校对”。顶部新增“先明确业务问题，再校对模型”。
2. 点击“载入质量场景示例”。确认框会说明：替换的是当前未保存编辑，不是服务器草稿。取消则保留原编辑。
3. 查看四个示例对象：物料主数据、原料批次、库存项、质量异常。它们是教学结构，不是从真实 ERP 或 WMS 发现的数据。
4. 修改业务目标和逐行验收问题。例如“同一物料的不同批次是否区分”“异常处理中是否避免重复建议调查”。这些问题用于人工验收，不会自动编译成测试代码。
5. 选择质量处置判断的作用对象。当前仅支持内置 `quality_disposition@1.0.0`，关联 `create_quality_investigation` 草稿工具。绑定表示能力依赖，不授予执行权限。
6. 选择对象卡片，校对其粒度、主键、来源、字段及数据分级。新对象可作为独立类型，不必强行归入五类旧核心锚点。
7. 展开“关系证据与时间范围”，检查建模声明、观察、推断、人工确认等来源性质。人工确认必须填写证据说明；时间范围结束必须晚于开始。
8. 保存草稿，再校验和模拟构建。修改未保存时不能使用上一次校验结果继续构建或登记。
9. 展开“判断回放”查看内置案例的预期结果、实际结果和通过状态。
10. 正式登记仍需要发布权限及独立语义服务成功登记。服务未连接时，本地结构演练不等于 Semantica 构建完成。

直接改为通用模式不会自动删除现有 OA 对象、状态机或治理资产。移除对象后，相应状态机、指标、契约和策略的失效引用必须一并处理；不要把“换模式”理解为自动完成模型迁移。

## 对象粒度如何选择

| 粒度 | 示例 | 应避免的混淆 |
| --- | --- | --- |
| master | Material、ProductSKU | 物料定义不等于某一到货批次 |
| batch | RawMaterialBatch、FinishedGoodsBatch | 同一种物料的多个批次不是同一个对象 |
| inventory_item | Inventory | 批次不同仓库、不同库存状态下的数量需明确粒度 |
| transaction | 采购单、订单 | 单据头与单据明细按业务动作范围区分 |
| event | QualityEvent | 质量异常不是被影响批次本身 |
| organization | 组织 | 组织主身份与历史归属关系分开 |
| unspecified | 待明确 | 兼容旧模型，不能当作粒度已完成治理 |

旧 `RawMaterial`、`Product` 锚点增加了身份语义说明，保留原编号及引用。此轮未执行主数据、批次、SKU 的历史拆分迁移，也未实现自动跨系统实体归并。

## 质量判断的实际能力

输入是已经过调用方权限裁剪的目标编号、来源风险等级、当前状态、证据引用。判断承接来源等级，不重新计算检验严重度。

| 输入情况 | 输出 | 是否执行动作 |
| --- | --- | --- |
| 待确认，P0/P1，目标与证据完整 | 建议复核影响并考虑调查草稿 | 否 |
| 待确认，P2/P3 | 建议人工复核 | 否 |
| 处理中或已审批 | 先核对已有任务和回执 | 否 |
| 已关闭或已解决 | 可复盘，不重复建议调查 | 否 |
| 缺少目标、证据，等级或状态未知 | 需要人工复核 | 否 |

智脑现有非定向质量分析入口已调用同一个判断实现，并返回能力版本、依据和只读状态。已发布的模型绑定会附加版本关联；草稿修改不会覆盖已发布定义。未配置模型绑定时，原有内置分析仍可运行。

绑定现在支持手动选择业务标识、来源风险等级、业务状态对应的源字段，并配置建议调查等级和证据有效期。仅允许当前对象的直接字段，不执行路径表达式、脚本或 SQL；旧绑定未配映射时仍是声明。已发布 QualityEvent 映射及参数接入现有非定向质量分析；不自动为任意新对象生成工具，指定业务编号的查询仍沿用原链路。

## 配置字段和参数

在“判断输入与参数”中选择三个字段。质量示例默认 `id → risk_id`、`severity → severity`、`status → status`；风险等级沿用 P0–P3，状态沿用表中支持的值，不做隐式中文或编码转换。

“建议调查的风险等级”至少选择一项，默认 P0/P1；“证据最长有效期”接受 1–10080 分钟，默认 60。过期证据返回需要复核，未来证据、错来源和越权记录拒绝。调整参数只改变建议，不重算来源风险、不授权执行。参数与映射随模型指纹一起版本化。

## 上传样本做版本回放

1. 保存草稿，展开“授权样本回放”。回放按钮在未保存编辑或没有校验权限时禁用。
2. 将 [两条合成案例 JSON](../../examples/semantic-schemas/quality-case-replay.json) 的完整内容粘贴到文本框。这个示例只适用于有对应组织权限的 Demo 身份，不是企业历史事实。
3. 点击“运行只读回放”。默认质量示例应为 2/2：P1 待确认建议调查，过期证据要求复核。无已发布版本时显示无基线；存在发布定义时用同一批样本比较两个版本。
4. 若将建议等级改为仅 P0，保存后重新回放，第一条预期应失败。这表示规则变化影响了验收用例，不能简单把失败改成通过。
5. 需要发布门禁时，在“发布验收”选择额外要求回放，保存、校验、模拟后，由发布人亲自运行当前草稿样本。其他用户的报告和旧指纹报告不能替代。

每批 1–100 条案例；界面限制 250 KB。每项包含 `id`、`objectType`、`at`（回放时刻）、`expected` 和 `record`。记录必须带 `tenantId`、`organizationId`、`classification`、来源 `system`、`objectType`、`id`、`version`、`occurredAt` 和业务字段 `payload`。身份由服务端认证确定，正文中的租户或组织只作为待核验数据。任一记录越权则整批拒绝，不返回部分结果。

回放不调用大模型、不创建业务任务；只持久化结果、指纹及来源版本，不保存原始 payload。这里接受的是调用方提供的有范围声明样本，不自动从企业库取历史、不证明来源真实性，也不覆盖完整自然语言多轮对话。

## 关系历史回放

回放入口支持 `kind: relation_history`。先载入并保存质量场景示例，再在“授权样本回放”中导入 [关系历史 JSON](../../examples/semantic-schemas/temporal-relation-replay.json)，点击运行。导入只填入编辑框，不自动请求；修改输入会清除旧报告。

两条案例查询同一个业务时刻：9 月 3 日。第一条只使用截至 9 月 3 日已记录的信息，物料 M1 与批次 B1 的关系有效；第二条使用截至 9 月 6 日的信息，包含 9 月 5 日补录的“关系已于 9 月 3 日结束”，因此该时刻没有有效关系。两项预期均应通过。

| 字段 | 含义 |
| --- | --- |
| `at` | 业务有效时刻 |
| `knownAt` | 系统已知的截止时间，不早于 at |
| `query.from/to` | `{objectType,id}`，两个具体实例 |
| `query.predicate` | 当前模型声明的关系 |
| `records` | 1–200 条端点身份记录，携带租户、组织、分类、版本、来源及发生时间 |
| `relations` | 最多 500 条关系修订，同样必须通过身份范围校验 |
| 修订 `validFrom/validTo` | 包含起点、不包含终点的生效区间，结束可为空 |
| 修订 `recordedAt` | 修订被记录的时刻，含时区 |
| 修订 `id/version/system` | 来源系统内稳定关系编号及版本；不按版本字符串猜先后 |
| 修订 `retracted` | true 撤回该来源断言，不删除以前已知的历史 |
| 修订 `provenanceType/evidenceIds` | 来源性质及非空证据引用；不证明来源已经外部核验 |

同一系统/关系编号采用截止时间内最后记录的修订；修订是完整有效期快照，不是局部时间段补丁。修订不能更换端点、谓词或所属组织；改变身份应使用新关系编号，并结束或撤回原断言。撤回不能消除其他来源记录。

`related` 表示提供样本中有有效关系；`not_related` 只表示这批样本中未见有效关系，不断言公司全量数据中不存在。同一记录时间的竞争修订、违反模型 1:1 / 1:n / n:1 约束返回 `conflict`；推断/建模声明、超出模型关系有效期、端点当时尚不可知返回 `needs_review`。

冲突保守检查样本内与查询同类型、同谓词的关系集合，不自动选赢家、合并主键或写回源系统。全部端点及修订先过权限，包括晚于截止时间的修订；任一越权整批拒绝。这不是全量时态数据库，不提供自动身份归并、分页遍历或多跳历史图查询，样本完整性仍需验收。

## 跨系统编号核验

在模型校对顶部选择“载入跨系统编号示例”，确认并保存。该教学模型明确允许 Material 来自 ERP、WMS，不会发现真实数据或迁移编号。随后在授权样本回放中导入 [编号映射 JSON](../../examples/semantic-schemas/identity-mapping-replay.json)。第一项是两个不同来源编号都有明确映射，第二项是两个系统编号均为 001 但没有映射；预期为“映射指向同一对象”和“缺少有效映射”，两项都应通过。

身份案例使用 `kind: identity_mapping`、`at`、`knownAt`、`query.left/right`、`records` 和 `mappings`。左右查询均是 `{system,objectType,id}`；编号精确匹配，不改大小写、不移除前导零、不按名称或相似度猜测。

每条 mapping 包含：

- 标准范围元数据：`id/version/system/tenantId/organizationId/classification/occurredAt`。
- `source`：带系统、类型、编号的来源引用；对应 records 中的一条授权记录，组织须一致。
- `canonical`：`{objectType,id}`，明确指定的统一编号；类型必须与来源一致。
- `granularity`：必须与模型对象粒度一致，不能为未指定；不能把主数据、批次、库存项互相当作身份别名。
- `validFrom/validTo/recordedAt/retracted`：完整修订、有效期和撤回语义与关系历史回放一致。
- `provenanceType/evidenceIds`：非空证据引用；只有 confirmed 才能形成已确认映射结果，observed/inferred/declared 均要求复核。

结果含义：`same_entity/different_entity` 仅表示提供映射指向相同/不同统一对象；`unresolved` 是没有有效映射；`conflict` 是同一来源存在多个统一编号或竞争修订；`needs_review` 是映射未确认或端点在当时尚不可知。confirmed 是上传样本声明，不等于系统已经验证了企业审批或来源真实性。

不同来源系统内相同的编号或映射记录 ID 不会自动合并。同一映射断言不能通过新版本偷偷更换来源、统一编号或组织；重分配必须使用新断言，并先显式结束/撤回旧断言，重叠时按冲突处理。所有样本先过权限，包括未来修订；任一越权整批拒绝。

当前只做有界显式映射核验、版本比较和结果留存，不维护企业主数据注册库，不做传递式别名推理、模糊匹配、自动历史迁移或业务写回。每案例最多 200 条来源记录、500 条映射。报告不保留原始 payload、来源编号或统一编号；保存的是判定、范围说明与统计。企业真实编号映射仍须数据治理和联调确认。

## 发布结果不确定时

人工登记与运营 Agent 发布共用发布协调器：先核验构建和可选回放门禁，再以固定版本请求独立语义服务，核对精确版本与模型指纹，最后比较本地草稿是否仍相同。并发发布被阻止，已发布版本不重复提交。

若超时或回执不匹配，状态保留为待对账；再次操作只查询同一版本，不自动重发。若发布期间修改了草稿，本地不会将新内容登记成旧版本。应核对独立服务部署，并恢复本次原草稿进行对账；无法取得一致回执时由运维处理，不通过删记录或重试新版本掩盖问题。当前没有自动回滚外部部署、跨服务分布式事务或真实 ERP 补偿。

## 执行结果与权限

模型中的动作依赖只是声明。真正创建调查仍走现有目标绑定、IAM、服务端工具白名单和一次性确认，不能用“分析一下”或模型里新增一个动作名称代替授权。

采购演示回执明确包含：

```json
{
  "sourceMode": "mock",
  "receiptStatus": "simulated_only",
  "externalReceipt": null,
  "businessCompleted": false
}
```

演练草稿与模拟审批不代表真实 ERP 受理。生产模式或禁用 Mock 后，这条尚未接入真实连接器的采购写路径会拒绝执行，不会以本地状态冒充外部成功。

## 不能据此宣称完成的事项

- 模型时间元数据已用于有界实例样本查询；尚不是全量数据库时态引擎，也未自动接入智脑自然语言业务查询。
- 九个回放案例是合成判断测试，不是上传材料、完整对话、跨系统追溯或历史业务回放。
- 依赖影响分析覆盖模型中已声明的判断与动作绑定，不自动扫描所有外部报表、流程和数据库消费者。
- 数据契约、质量规则和访问声明的结构合法，不代表其全部表达式已经被运行或已获得权限。
- 发布保存模型版本，不代表 ERP 已接入；草稿快照回滚不会撤销已经发生的业务操作。

测试证据见 [本体建模改进验收](../development/ONTOLOGY_MODELING_ACCEPTANCE.md)。生产剩余事项统一见 [Checklist](../operations/PRODUCTION_TODO_CHECKLIST.md)。
