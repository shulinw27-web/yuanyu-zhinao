# 知识资料、理解草稿与记忆校对指南

更新：2026-09-13。适用：智脑桌面/Web/移动工作台、语义运营 Web/Electron。

## 1. 两端入口

智脑侧进入“知识资料”；移动布局进入底部“资料”。语义运营侧进入“04 知识资料”。资料隔离键包含企业、已认证主体和原始角色：登录同一个企业账号但角色不同，也不能默认互读。

该入口提供原文检索，以及管理员开放后的来源约束模型问答。普通业务聊天不会自动注入整库资料。WeKnora 独立问答与本项目知识提供方接入是不同链路，不能因为前者成功就宣称后者已经联通。

## 2. 保存和校对资料

1. 新建资料，填写标题、来源、版本和正文。支持导入 TXT、Markdown、CSV、JSON 文本，文件上限 240KB、正文上限 120000 字符。CSV/JSON 在这里作为文本处理，不宣称完成表格语义解析。
2. “预览分块”只展示解析结果，不保存。偏移是 UTF-16 文本偏移，不是 PDF 页码。PDF、图片、Office 等可使用本页“多模态材料校对”，操作见第 8 节；精细图像区域与模型候选连线尚未实现。
3. 人工核对后“确认保存个人资料”。保存不是正式制度发布；服务端检查按钮权限、内容安全、修订号及限额。
4. 同时有人修改时拒绝覆盖，刷新并重新打开当前版本。内部切换资料时会提醒放弃未保存编辑；离开整个页面前仍应先保存，草稿没有浏览器自动恢复机制。
5. 撤回需要输入“确认撤回”。撤回后停止检索、旧引用无法读取；不物理删除历史修订或电脑上的原始文件。

每个隔离工作区最多 64 份资料，单文档保留最多 10 个修订，存储上限 2MiB。达到修订限额仍允许撤回，不用删除限制阻止撤权。

## 3. 查询和来源复核

选择“本人资料”或已配置的“WeKnora”。输入问题后“查找原文依据”，再“重新核验并打开引用”。没有相关内容就明确返回无依据；来源变化或权限不符时停止返回旧引用，不回退到越权数据。

制度可以解释“资质过期如何处理”，不能代替实时系统回答“本批影响多少订单、损失多少钱”。后者仍应通过已发布语义模型与企业数据连接器查询。

## 4. 业务理解草稿 / Wiki

检索后展开“业务理解草稿 / Wiki”，根据本次来源新建主题，填写人工理解笔记并确认保存。每份草稿最多 5 个引用，每工作区最多 20 份草稿；人工笔记最多 8000 字符。持久化来源标识而非原文副本，再次打开时重新读取和复验资料。

笔记始终为未验证理解；多份来源同时列出，不自动裁决哪份权威。“自动整理来源提纲”无需模型，只整理引用目录；“生成待校对 Wiki 草稿”则真实调用已确认模型，结果须人工打开校对后保存。已有笔记不会被自动提纲覆盖。

“来源冲突提示”仅比较明确的同名“字段：值”，不代表通用语义冲突检测。历史保留最近 10 个旧版，打开旧版也核验来源。输入“确认恢复”后恢复成一个新修订，不覆盖原修订；来源被修改、撤回或撤权后不能打开、恢复或交接旧内容。存在并发修改时拒绝覆盖。

语义运营侧可点击“核验并填入建模输入框”。系统仅切换到 Agent 页并填入待审阅文本，不自动发送、采纳或发布。超过 8000 字符需拆分主题。之后继续走原有候选建模、人工校对、校验及发布门禁。智脑业务端不提供这个建模按钮。

## 5. 智脑长期记忆

智脑资料页可展开长期目标记忆，查看完整内容、来源、角色和到期时间。目标仍由用户在任务中明确固定，不新增后台自动提取。

“校对 / 修改”需要输入“确认修改”，服务端按指纹检查是否已变化。修正不延长原 90 天保留期，不改变原聊天和任务目标，也不授予执行权限。“删除”需明确确认，删除后不再跨会话使用；原聊天、审计记录和已发生的业务操作不会因此消失。语义运营记忆不借用业务用户记忆。

修改和删除会同步更新右侧记忆摘要。删除后可以重新主动固定当前任务；固定按钮不再仅按历史 `pinnedMemoryId` 判断。说明“我的长期目标是……，只讨论不执行”属于目标陈述，不自动查询默认告警，也不自动固定为长期记忆。

## 6. 管理员配置 WeKnora

使用 [不含密钥的模板](../../examples/knowledge/weknora-config.example.json)，复制到仓库外的私有目录，例如 `D:\wsl\private\yuanyu-zhinao\weknora.local.json`。不要把方舟模型 Key 当作 WeKnora API Key。

必要字段：`schemaVersion: 1`、`enabled: true`、WeKnora API Key、回环地址、超时及明确资源绑定。后端进程设置 `WEKNORA_CONFIG_FILE` 为该文件绝对路径。前端只显示配置状态，不读取密钥。

`bindings` 中每项包含：

```json
{
  "principalKey": "服务端解析身份的 SHA-256 指纹",
  "tenantId": 10000,
  "knowledgeBaseId": "获准使用的知识库 ID",
  "knowledgeIds": ["获准使用的文档 ID"]
}
```

指纹在资料页“管理员接入诊断”显示，由服务端 `knowledgePrincipalKey(context)` 计算，输入为 `identityScope.tenantId`、`identityScope.subjectId`、`roleId`。它不是密码、不授予权限。必须根据实际登录后的主体制定映射，不能用显示名称猜测。重复主体绑定、空文档集合、缺少绑定均拒绝。

默认 `retrievalMode: keyword_only`。显式改为 `hybrid` 后允许 WeKnora 向量和关键词混合召回，仍限制文档白名单并复验原文；重排尚未配置。混合模式会产生向量模型调用费用，不应在没有测试预算时自动开启。

每次授权复验都会重新读配置，不缓存权限。删除绑定或轮换 Key 后，旧请求拒绝继续读取。接口只允许 `http://127.0.0.1`，拒绝任意外网地址、重定向或 URL 内的凭据；不自动重试，不传回上游错误正文。

当前专用只读 Key 和原合成制度绑定已配置，真实接入见第9节。新增联调材料仅在隔离测试进程绑定，不会自动扩大常驻账号的文档范围。企业共享、员工离职撤权及文档保留/删除政策仍需要真实企业确认；本指南不代表这些已上线。

已准备隐藏输入的配置助手；用户确认并创建专用只读 Key 后，可在 PowerShell 或 CMD 中运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\wsl\workspace\project\demo-platform\scripts\save-weknora-config.ps1"
```

按提示填当前主体指纹、WeKnora 空间 ID、获准库/文档 ID，再隐藏输入 WeKnora Key。文件保存在 `D:\wsl\private\yuanyu-zhinao\weknora.local.json`，不显示 Key，不覆盖已有文件。`Bypass` 仅作用于这次进程，不修改机器执行策略。助手要求私有目录已经存在且 ACL 仅当前 Windows 身份可访问，未通过则不写入。

## 7. 依据资料连续问答与生成 Wiki

管理员先完成资料出网评估，再在 API 服务进程设置 `KNOWLEDGE_MODEL_ALLOWED_MODES`，例如只允许 `ark`；默认空，不发送个人资料。原有方舟接入仍须配置且通过模型准入。本轮真实测试仅在隔离进程临时开放合成资料，没有修改常驻生产配置。

1. 检索并查看当前依据，确认资料范围。
2. 在“与本次资料对话”查看 provider/model 和传输说明，确认有权发送所选资料。
3. 输入问题并选择“依据资料回答”，或“生成待校对 Wiki 草稿”。只保留最近 6 个用户问题（总长 6000 字符），每轮重读来源，不回填旧模型答案。
4. 展开“核验依据”查看服务端从原文回填的片段。引用存在不保证解释正确，仍需判断业务语义；没有实时业务数据时明确未知。
5. Wiki 结果通过上方“打开模型生成草稿并人工校对”进入编辑。保存和建模交接仍是独立确认步骤。

更换检索来源或模型后清空本轮上下文与确认。模型故障、引用无效、权限或资料变化不会降级成成功话术；重新检索和确认后再试。该入口不创建工单、审批或操作电脑，主业务查询仍使用既有语义模型。

补充：问答提示“当前引用不足”时，输入具体追问，点击“在所选文档内补查并预览”。只在原选定文档中再检索，每提供方一次，最多五条；不调用回答模型。核验新片段后重新勾选模型发送确认，才会使用这些片段回答。来源或模型改变时旧结果失效；不会扩大到整库或把原文当作业务执行授权。见 [修复及验证边界](../development/DUAL_AGENT_WEKNORA_REPAIR.md)。

## 8. 多模态材料人工校对

展开“多模态材料校对”，选择一份不超过 4MB 的 PDF、图片、DOCX、XLSX、CSV、JSON 或 YAML。确认使用配置的内容安全与解析服务后开始；扫描件和图片可能需要获准 OCR/视觉服务，没有配置时不能根据文件名猜测。

左侧预览本地图片/PDF；右侧选择片段、核对解析器位置和文本，填写人工修正。Excel 保留工作表/单元格标记，Word 保留段落/表格标记，不宣称是渲染页。没有原图区域坐标就不显示虚构框选。截断、未识别页、公式缓存等限制会一并提示。

确认核对后“转入资料编辑框”，检查标题、来源和正文，再确认保存个人参考资料。不会覆盖电脑上的原文件，也不会把校对者提供的定位当成服务器认证事实。当前编辑框有未保存内容时拒绝覆盖。离开页面会释放原文件预览和未保存解析结果；本入口不新增二进制文件存储。

## 9. 本机真实接入与复现（2026-09-13）

专用只读 Key 和私有文件已配置；只允许演示管理员 `admin@demo.local` 读取唯一合成库的一份制度，其他账号默认无绑定。正常启动 API 时显式指定：

```powershell
$env:WEKNORA_CONFIG_FILE = 'D:\wsl\private\yuanyu-zhinao\weknora.local.json'
npm run start:ark
```

两端使用同一 API，登录管理员后进入资料页，选择 WeKnora，检索“原料异常”。查看原文及引用，再按第7节完成本次模型使用确认。Key 配置不自动开放知识资料出网；若 `KNOWLEDGE_MODEL_ALLOWED_MODES` 未设置，模型按钮禁用是预期行为。正式环境须先审查数据分级，不能为试用将全部企业资料开放。

`npm run evaluate:weknora -- --live-synthetic --hybrid` 在隔离项目 API 下检查双端读取和权限拒绝，再调用真实混合适配器；`--live-synthetic --answer` 检查双端各三轮方舟问答。无参数不发请求。测试只接受既定合成库/文档绑定，结束关闭测试 API，不修改常驻服务策略。生成摘要不作为原文引用，默认状态0和已索引状态2的文本可读，待处理状态1仍拒绝。

图形保存助手 `scripts/weknora-credential-intake.mjs` 是管理员显式启动的一次性工具，不是常驻 Web 管理接口。启动前以 `WEKNORA_SETUP_BINDING` 提供已批准的非敏感绑定元数据（principalKey、tenantId、knowledgeBaseId、knowledgeIds），密钥只能在隐藏输入框填写，不能作为启动参数。固定写入同一私有文件、拒绝覆盖；现有配置无需再次运行。用户仍可采用第6节 PowerShell 隐藏输入助手。

## 10. 业务端联合核验

先由语义运营完成模型的校验、正反例回放和发布，并配置服务端对象读取权限与连接器。业务用户登录智脑知识资料页，检索需要参照的制度后，展开“知识依据＋业务事实 · 只读联合核验”。

先查看“已发布读取方案”：目录显示名称、根对象类型、输出口径和模型版本。仅一个方案时预选；有多个方案时必须明确选一个。目录不读取业务记录，也不授予对象权限。没有方案时，确认和提交按钮禁用，先检查运营发布、服务端元数据及对象授权。

填写核验问题和选定方案要求的根对象编号，最多3个、逗号分隔。例如，在跨渠道履约合成场景已发布后，使用 `ORD-X900` 核验库存与信用缺口。不要将示例编号用于其他模型；系统不猜测默认业务对象。

勾选本轮只读确认，再开始核验。页面分别展示当前授权业务计算、所选资料原文和覆盖边界，不判断制度是否适用，不触发工单、审批、解冻或付款。此流程不调用模型，也不受知识模型出网开关影响；业务对象授权仍必须具备。无发布模型、多个未选择读取方案、缺少数据或版本变化会拒绝返回，不能把它视为“计算为零”。

该控件只在业务端出现，语义运营端继续负责资料整理和建模。当前联合核验不自动继承聊天里的编号，也不执行自动补查；必须明确输入，后续联合规划仍在清单中。

页面会附带本次看到的模型版本及指纹。若运营人员在此期间重新发布，服务端拒绝使用旧选择读取业务；点击“刷新已发布读取方案”，重新检索资料并核对编号后，再勾选确认。结果中记录本轮实际方案和模型版本，不能把不同口径的两次结果混为一份。
