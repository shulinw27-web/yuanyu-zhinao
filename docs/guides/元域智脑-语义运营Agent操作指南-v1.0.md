# 元域智脑｜语义运营 Agent 操作指南

版本：V1.0  
适用端：语义运营 Agent Web 端、Windows 桌面端  
更新日期：2026-08-27

## 1. 这套工具用来做什么

语义运营 Agent 面向平台运营、数据治理和语义建模人员，用于把业务语言、数据字典和接口材料整理为可审阅的语义模型草稿。它与业务端“智脑”分开：智脑负责查询、分析和业务协作；语义运营 Agent 负责模型建设、校验、模拟、版本管理和受控发布。

Agent 可以生成建议和执行计划，但不会因为一句自然语言就直接改模型。凡是涉及写入草稿、校验、模拟构建、发布或回滚的动作，都受权限和确认机制约束。

## 2. 使用前准备

### 2.1 运行条件

- 后端治理 API 可访问，默认地址为 `http://127.0.0.1:3001/api`。
- Semantica 服务可访问，默认地址为 `http://127.0.0.1:3011`。
- Web 端默认地址为 `http://127.0.0.1:5174`。
- Windows 桌面端推荐使用 1920×1080 或更高分辨率；系统缩放为 125% 或 150% 时也可正常使用。

### 2.2 建模物料

自然语言可以启动任务，但真实建模最好同时准备以下材料：

- 系统名称和业务边界，例如 ERP、WMS、OA、MES、LIMS、QMS、OMS。
- 数据字典或表结构，至少包含表名、字段名、字段类型、主键和字段说明。
- OpenAPI、JSON Schema、接口示例或 CSV 样例。
- 跨系统关联规则，例如采购单号、批次号、供应商编码的传递关系。
- 数据分级、可见范围和角色要求。
- 需要计算的指标、业务术语、质量规则和发布范围。

当前支持上传 PDF、PNG/JPG/WebP 图片、JSON、YAML 和 CSV。上传内容只进入当前任务的受控分析流程，不等同于获得其他系统的访问权限。

## 3. 界面结构

### 3.1 Agent 工作台

用于新建任务、上传材料、查看 Agent 计划、审阅模型提案和执行确认。左侧任务窗口保存各项任务，右侧为当前任务的完整对话和证据记录，输入区固定在任务窗口底部。

### 3.2 模型校对

用于人工调整 Agent 生成的对象、字段、关系和语义治理资产。该页面包含：

- Semantica 候选对象库；
- 业务对象画布和关系图；
- 对象属性、主键、字段及来源系统；
- 指标、业务术语、数据契约、质量规则；
- 访问策略和数据血缘；
- 保存、校验、模拟构建和登记模型入口。

### 3.3 版本与回滚

用于查看每次采纳形成的草稿快照、对象与关系 Diff，以及执行受控恢复。回滚只恢复未发布草稿，不会自动撤销已发布的 Semantica 版本。

### 3.4 右侧状态区

状态区展示当前草稿对象数、关系数、可回滚快照、待复核冲突、权限闸门、模型状态和草稿/部署指纹。出现“草稿有未发布变更”表示草稿领先于 Semantica 已部署版本，不代表系统故障。

## 4. 建立第一个语义建模任务

### 第一步：确认角色

在右上角选择当前运营角色。界面会按角色重新加载权限、可见任务和模型能力。角色名称用于表达当前工作视角，最终是否允许执行仍以服务端权限校验为准。

### 第二步：新建任务

进入“Agent 工作台”，点击“新任务”。建议一次任务只解决一个明确目标，不要把多个无关系统和模型同时塞进一个任务。

可直接使用以下表达：

1. `分析 ERP 和 WMS，建立采购订单、到货单、入库单和库存之间的语义模型。`
2. `读取上传的数据字典，识别业务对象、主键、字段映射和跨表关系。`
3. `检查当前模型是否有重复对象、缺失主键或断裂关系。`
4. `为采购到入库流程补充到货及时率指标、数据质量规则和供应商访问策略。`

### 第三步：上传材料

点击“添加材料”，选择数据字典、接口文档、截图或样例文件。材料上传后再发送任务。涉及真实系统时，提示词中应写清来源系统和期望产物，例如：

> 根据上传的 WMS OpenAPI 和 ERP 数据字典，建立采购订单到入库库存的模型。采购单号为跨系统关联键；请标出无法从材料确认的字段，不要自行补造。

### 第四步：查看规划和来源预检

Agent 会先给出确定性任务意图、受控系统范围、执行计划和来源预检结果。重点检查：

- 识别的系统是否与请求一致；
- 是否出现范围外系统；
- 所需连接物料是否齐全；
- 哪些内容来自材料，哪些仍待人工确认；
- 当前任务是只读分析还是写操作。

若 Agent 建议了范围外系统，系统会标记冲突并按服务器判定裁剪，不会直接扩大访问范围。

### 第五步：审阅模型提案

模型提案会列出候选对象、关系、字段映射、结构校验结果和 Mock 映射演练。采纳前至少确认以下内容：

- 对象名称符合业务语言，编码稳定且不重复；
- 每个对象有明确主键；
- 来源系统和源对象可追踪；
- 关系起点、终点、谓词和基数正确；
- 必填字段已经映射，或明确标记为派生、忽略；
- Schema Critic 没有阻断项；
- Mock 映射演练没有必填字段缺失或转换错误。

需要调整时，在可视化编辑器中修改对象、字段、主键、映射方式和关系，然后点击“保存修订并重跑结构与映射演练”。旧确认令牌会随提案修订失效，必须基于最新版本重新确认。

### 第六步：显式确认执行

写操作准备就绪后，界面会显示确认按钮。点击确认后，服务器签发与当前任务、提案版本和草稿指纹绑定的一次性确认令牌，再执行写入。

以下情况会被拒绝：

- 重复点击或重复提交同一确认令牌；
- 草稿在确认后被其他窗口修改；
- 提案版本发生变化；
- 当前角色缺少所需权限；
- Schema Critic 或映射演练仍有阻断项。

任务显示“已完成”只代表本次受控命令执行完成。建立模型任务完成后，结果仍是未发布草稿，不代表已经发布到 Semantica。

## 5. 人工校对和发布流程

进入“模型校对”，按以下顺序操作：

1. 在候选对象库中选择需要加入草稿的对象。
2. 在对象属性区补齐业务名称、语义类型、来源系统、主键、数据分级和说明。
3. 在关系编辑器中校对对象关系和基数。
4. 展开“语义资产与治理契约”，补充指标、术语、数据契约、质量规则、访问策略和血缘。
5. 点击“保存草稿”。
6. 点击“校验草稿”，解决所有阻断项。
7. 点击“模拟构建”，验证 Semantica 模型定义和 Mock 数据闭环。
8. 由具备发布权限的角色点击“登记模型”。

发布前要重点核对草稿指纹、部署指纹和影响范围。若状态为“草稿有未发布变更”，说明仍有变更没有进入已部署版本；若状态为“草稿与部署一致”，说明当前草稿与 Semantica 登记版本一致。

## 6. 任务管理

任务窗口支持按关键字和状态查询，也可以包含已归档任务。常见状态含义如下：

- `等待确认`：方案已经生成，写操作尚未获得本次执行授权。
- `执行中`：服务器已占用执行租约，正在处理。
- `可重试`：上次执行未完成，可以在排除原因后重试。
- `已完成`：本次命令已经完成；是否发布需看命令类型和模型状态。
- `已阻止`：权限、校验、材料或安全边界不满足。

归档只隐藏任务，不删除审计证据。相同租户和用户身份可在其他设备继续查看任务，但设备切换不会继承一次性执行授权。

## 7. 版本和回滚

每次模型提案被采纳时，系统会保存采纳前草稿快照和结构 Diff。需要恢复时：

1. 打开“版本与回滚”。
2. 展开目标快照，核对对象和关系变化。
3. 点击“恢复此快照之前”。
4. 阅读影响说明，输入 `确认回滚`。
5. 点击“确认恢复草稿”。

如果当前草稿已经存在后续改动，服务器会拒绝覆盖式回滚。此时应先比较 Diff，决定保留后续变更还是建立新的修订任务。

## 8. 权限和安全边界

- 自然语言不是授权。用户写出“帮我发布”不代表系统获得发布权限。
- 长期记忆不是授权。历史任务中的确认不能用于当前任务。
- Agent 不能绕过 Review Queue、Schema Critic 或服务端权限校验。
- 未配置的 ERP、WMS 等连接不会被当作真实已接入数据源。
- 不应在任务中上传口令、私钥、数据库连接串或生产 Token。
- 涉及删除、发布、主键变更和回滚时，必须确认目标版本与影响范围。

## 10. 常见问题

### 输入框不在窗口底部

先确认使用的是 V0.2.0 之后的桌面包。调整窗口到至少 960×640；若 Windows 显示缩放过高，可将窗口最大化。输入区固定在任务对话窗口底部，页面下方的状态卡片可以继续滚动查看。

### 无论输入什么都得到相同回复

检查后端 API 是否可访问，并确认页面没有显示加载错误。只读状态查询、普通对话和建模任务应产生不同意图；若仍完全相同，记录任务 ID和请求时间，检查后端任务事件。

### 任务显示已完成，但模型没有变化

先看任务意图。状态查询和普通对话完成后不会修改模型。建模任务还要经过确认；确认完成后只写入草稿，发布到 Semantica 需要完成校验、模拟构建和登记。

### 模拟构建或登记按钮不可用

通常是草稿尚未保存、校验存在阻断项、当前角色缺少权限，或 Semantica 服务不可用。按“保存草稿 → 校验草稿 → 模拟构建 → 登记模型”的顺序处理。

### 提示确认失效

说明草稿、提案版本或任务状态已经变化。重新加载任务，核对最新 Diff 后再确认，不要反复提交旧按钮或旧令牌。

### 草稿有未发布变更

这是正常的版本漂移提示。确认这些变更是否应发布；如果只是测试模型，可保留在草稿，或通过版本页恢复到测试前快照。

## 11. 日常操作检查单

开始任务前：

- 当前角色与工作职责一致；
- 任务目标、系统范围和期望产物清楚；
- 数据字典、接口材料和关联键已经准备；
- 材料中没有密钥和生产凭据。

确认提案前：

- 对象、主键、字段、关系和来源系统正确；
- 所有不确定项明确标出，没有自行补造；
- Schema Critic 和 Mock 映射演练通过；
- 影响分析符合预期。

发布前：

- 草稿校验通过；
- 模拟构建通过；
- 数据契约、质量规则、访问策略和血缘完整；
- 草稿指纹、部署指纹和 Diff 已复核；
- 发布角色和审批要求满足。
