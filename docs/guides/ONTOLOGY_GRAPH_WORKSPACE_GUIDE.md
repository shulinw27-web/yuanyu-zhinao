# 图谱建模工作台操作指南

日期：2026-10-09。适用：元域智语模型总览、Agent 审核、知识资料及智脑授权读取结果。

## 本次编辑工作区

模型页的业务关系图、对象配置和关系修改共用同一份本次草稿。点击对象后选择“修改选中对象”，技术配置按需展开；点击连线可修改关系名称、基数和依据说明。保存、校验、模拟构建和登记操作始终可见，修改不会自动发布。

“撤销／重做”只恢复本次页面编辑，最多50步，并受历史内存预算限制，不是发布版本回滚。刷新、角色或服务端模型变化后清空历史。出现未保存修改时，校验及发布仍禁用；向 Agent 提问也要求先保存，避免旧修订解释新图。

校对问题可点击定位对象或关系。服务端部分结构校验返回字段和对象/关系目标，可直接跳转处理；有未保存修改时隐藏旧校验目标，无法确定目标的复杂错误只提供详情。“按关联自动布局”按关系方向排列，环路对象同层；只是视图变化，不改变业务关系。复杂关系的完整避让和领域折叠仍待完善。深化进度见[阶段计划](../development/ONTOLOGY_WORKSPACE_UPGRADE.md)。

## 看图和核对关系

进入“模型校对”，先查看业务对象关系图。点击对象看业务含义与来源，点击连线看基数、依据；字段与标识默认折叠。绿色、黄色和虚线红色分别表示新增、修改和删除，文字同时说明状态。修改关系时可查看修改前/后的基数和证据。

搜索名称、编码或系统；选择来源可缩小范围。选中对象后可只看它的邻居。箭头有方向，反方向无路径不代表没有任何业务联系，只说明模型未声明该方向。拖动不修改语义；“保存本次会话布局”先暂存布局，随后在“我的模型视图”点击保存，才会写入个人视图并生成跨刷新恢复链接。

模型超过100个对象时默认只显示前100个，可主动扩大到最多500个，或通过搜索定位范围外对象。大型模型优先搜索与邻居展开，不建议把所有字段一起展开。

Agent 任务中的图与总览共用组件。点击“向 Agent 提问”只将问题填入输入框；用户发送后才进入对话。未保存编辑不显示旧差异，需先保存修订并重跑校验，再确认采纳。审核采纳不是发布。

## 看底层系统如何关联

展开“跨系统来源与字段映射”，选择一个对象。图中显示系统、业务对象、映射字段与引用目标；节点详情说明源表/API、源字段、主键及映射状态。缺少资料时明确显示未登记或待核对。这里是模型的映射声明，不能证明 ERP/WMS 连接已通。

展开“用问题定位模型路径”，例如输入“采购订单与供应商有什么关系”。支持对象别名和指向该对象的业务术语；选中对象后可以问“它与生产批次有什么关系”。询问单个对象的含义可获得模型解释。同名或同别名目标使用编码区分，不会自动合并实体。数量、金额、库存等问题需要智脑的已发布只读计划及业务编号，不能用类型图的节点数回答。

## 从模板开始与格式导入

“从业务模板开始”有采购收货、生产质量、仓储履约和 OA 内部事务四类。先看候选关系和同名冲突，再带入 Agent 输入框。模板不会自动选择企业系统、猜测字段、覆盖对象或发布。按“建模上手路线”依次提交材料、核对关系、修订提案、校验、模拟构建和受控发布。

“行业 Mock 方案包”提供采购、生产、履约和入职四类合成材料，包含 API、数据字典、需求、样本分叉和验收问题。点击“将完整 Mock 材料交给 Agent 核对”交接原文；用户仍需核对来源、授权与建模提案，不能将示例当作真实企业数据。

字典为结构化JSON；包内 `suggestedReadPlan` 是只读分支统计候选，需要人工审阅、回放和发布，不带运行授权。开发验证可运行 `npm run test:ontology-industry`：4类材料解析到发布和智脑读取使用Mock连接器回归，不代表真实模型对话效果已验收。

“模型交换”提供平台结构包、中立 JSON-LD 与 Playground 参考 RDF/XML 子集。平台结构包保留系统及字段映射声明，中立配置不带系统映射。字段类型、主键、单位、枚举可往返；不导出授权、凭据字段、业务实例或执行计划，不执行 OWL 推理。不支持通用 Turtle、任意 RDF/XML 或完整 Playground 注解；损失报告须人工查看，外部类缺少字段/主键时拒绝。文件上限240KB，禁止 DTD 和实体声明，不访问远程地址。原文和转换结果先预览，再显式交给 Agent；导入不直接写入模型。

## 将资料关联到业务对象或关系

在知识资料“查找依据”先检索，再到“资料与业务对象关联”。可以手动选择对象或关系，或“按明确名称查找候选”（不调用模型）。管理员启用资料模型策略后，可勾选同意将本次选定片段及目标目录发送到显示的提供方/模型，再点击“AI 分析已检索依据”。模型建议必须引用本次可读片段、选择当前模型目标，调用前后重新核验。未配置策略、服务不可用或目标编造会明确失败，不生成假AI建议。目标目录超过2700字符需缩小范围。建议不证明制度权威性，均不自动保存。

逐条核对片段和目标，选择关联含义，勾选确认后保存。对象版本、关系或原文发生变化时，旧关联提示重新核对；失效原文不继续展示。记录区可核验原文或撤回。关联仍按企业、主体、角色隔离，不会因为共享模型审核而自动向他人开放私有资料。

## 分享模型与查看智脑实例图

选择对象后生成模型定位链接。链接只携带指纹与对象编码，不能绕过登录和权限。接收人的当前模型不匹配时拒绝定位，不自动加载历史版本。部署在本机的127.0.0.1链接只在本机有效；团队需使用同一已部署站点地址。

智脑完成已发布模型的授权读取后，回答可展开“本轮授权读取的业务实例关联图”。它展示实际记录编号、来源、版本及声明外键匹配，不是建模类型图。缺失数据不补造，不把关联当作根因或审批通过；预算超限会提示部分连线未展示。刷新、重新登录或恢复历史对话需重新查询，不把旧图当作当前授权。

实例图还列出已发布业务关系：快照内匹配、快照内无匹配、未声明引用、映射歧义、需要执行主数据映射。最后一种不会按相同字段值冒充对齐，也不通过同字段的底层外键连线绕过；依赖未执行映射的读取计划会在查询前拒绝。显式绑定版本化、确认的对照对象后，成功读取可显示“快照内已通过确认的主数据映射关联”。无匹配不等于企业范围内不存在；逆向转换和递归转换尚不支持。配置与限制见[主数据映射指南](ONTOLOGY_MASTER_DATA_MAPPING.md)。

### 复杂关系图怎么查看

先点“按关联自动布局”，再按来源系统或所选对象的邻居缩小范围。“按来源系统缩小范围”提供对象数量和快捷按钮，多来源对象在各来源中分别计数；需要看跨系统路径时切回“全部来源”。这不是主数据合并或业务域折叠。

对象较多时点“来源分组总览”。每个对象按完整来源集合只归入一组，例如ERP/WMS多来源对象单独成组；未声明来源单列。组卡列出对象数及组内关系，组间箭头列出原始关系数，正反方向和待删除关系分开。这里只汇总当前筛选中的声明，不意味着系统接口已打通，也不推断影响或因果。

点“展开组内对象”看该组的原始模型图；点组间“查看原始关系”看指定方向的原始连线。页面会提示哪些关系被隐藏，可点“恢复当前筛选的全部关系”或“返回分组总览”。分组较多时按需加载更多，详细图仍最多展示500对象，完整路径需结合显示范围核对。总览不保存为业务对象或个人布局；外部对象/路径定位会退出分组视图。

并行、反向及自关联分别显示曲线。关系文字会避让节点和其他文字，拥挤时提示收起的文字数量，但不会删掉连线；点击连线、鼠标停留或用Tab选中后按Enter，可查看完整名称、基数和依据。拖动对象后会重新计算文字位置。图说明已声明结构或本轮授权快照，不证明根因和完整影响范围。

## 个人视图与只读嵌入

在关系图暂存布局后，展开“我的模型视图”，输入名称并保存；支持新建或以修订比较更新，最多20个。保存会生成个人授权链接，刷新同一链接可恢复。切换租户、用户或角色不能读取原身份视图，模型变更后旧视图返回冲突，需重新保存。这里只保留布局，没有历史模型浏览或团队公开共享。

“登录后只读嵌入链接”使用 `?embed=ontology#saved-model-view=UUID`，登录及模型权限核验后仅展示模型图，不提供编辑、发布、布局保存或Agent执行入口；不显示业务记录或原始资料。本机地址不能被其他电脑直接访问，跨站iframe、SSO及真实企业部署另行验收。

## 业务域与连续模型对话（2026-10-09）

对象表单可选填“业务域”，例如采购、仓储、生产；未填写显示未归类，不根据ERP/OA等来源猜测。点“业务域总览”查看各域对象及跨域关系，再下钻到原始对象。该属性不授予数据权限、不证明业务系统已接通。

连线遇到对象遮挡时尝试有限绕行；无法解决会提示，不承诺复杂图完全无交叉。看不清连线时展开“原始关系列表”，直接点击关系查看名称、基数和依据。

校验提供精确目标时，可定位读取计划或治理配置。高级配置编辑器只修改该项，空集合问题则编辑对应对象数组；可撤销。草稿变更或撤权后旧编辑不能应用。修改不是保存，需重新保存、校验、模拟构建和审核。

在模型页选择对象后向Agent提问，会清除旧任务选择并填入问题，不自动发送。后端校验当前模型指纹和对象，旧版本需重新进入模型页。Agent获得的是结构元数据，不是底层业务记录。

同一待确认候选可明确提出`将“Supplier”的业务域改为“采购”`，也支持业务名称、业务说明、关系名称、关系基数、关系依据。用唯一名称或编码定位；歧义、未知目标及过期修订会拒绝。修改沿用同一任务与候选，但使旧确认失效；仍需用户确认、保存和发布。任意自由文本改写或自动发布不在此能力范围。

当前真实方舟调用因`ARK_ACCOUNT_OVERDUE`未通过，以上连续修订的确定性命令及Mock测试不等同于真实模型智能验收。
