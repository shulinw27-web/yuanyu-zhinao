# 国内协同平台接入指南

版本：1.0｜资料核对：2026-09-08｜适用范围：钉钉、企业微信、飞书、华为 WeLink、WPS 365，以及国内企业统一身份服务。

本指南以企业内部自建应用为主，不包含海外协同平台，也不把多企业应用市场上架当作本期接入。覆盖平台是项目选型范围，不是市场份额排名。平台后台会随版本变化，实际表单、权限和客户端支持范围以对应企业后台为准。

项目各端的构建、部署及登录桥见 [各端接入指南](CLIENT_ACCESS_GUIDE.md)；平台 IAM 与身份源配置见 [身份适配指南](IDENTITY_PROVIDER_ADAPTERS.md)。

## 1. 接入方式与当前进度

| 国内平台 | 本项目采用的接入路线 | 手机/PC 处理方式 | 当前进度 |
| --- | --- | --- | --- |
| 钉钉 | 企业内部 H5 微应用，专用免登 | 共用 H5，分别验收宿主 | 已有代码与模拟回归，待企业联调 |
| 企业微信 | 自建应用网页入口，服务端验证授权身份 | 端内网页和外部浏览器扫码分别设计 | 专用宿主与验码适配待开发 |
| 飞书 | 自建网页应用，宿主授权码与服务端登录 | 配置目标端入口并真机核验 JSAPI | 专用宿主与验码适配待开发 |
| 华为 WeLink | H5 轻应用；也可评估企业现有身份联邦 | 手机/PC 不假定 JSAPI 完全相同 | 专用适配待开发 |
| WPS 365 | 企业网页应用，用户授权及服务端身份绑定 | 根据 WPS 协作客户端能力逐端验证 | 专用适配待开发 |
| 国内统一身份服务 | 企业 OIDC，例如 Authing；其他产品先做令牌兼容性验证 | 各端接入登录宿主，共用 API 验签 | 通用验证已有，具体产品尚未联调 |

普通微信、公众号和个人小程序不是公司员工目录。除非另外建立可靠的企业员工绑定与审批，不应将个人微信登录作为本项目内部数据访问资格。

## 2. 不要混淆的四类集成

| 集成类型 | 交付结果 | 不能据此宣称 |
| --- | --- | --- |
| 工作台入口 | 用户能在协同平台打开网页 | 已完成免登 |
| 身份免登 | 已验证外部用户并绑定平台账号 | 已拥有所有公司数据权限 |
| 消息/机器人 | 收到通知或在会话中发起请求 | 已具备工作台全部交互和受控本机执行能力 |
| 数据/审批/文件连接器 | 按授权读写指定平台资源 | 获得无限访问权或免除业务确认 |

本期先接入口和身份；消息、通讯录、审批与云文档按实际业务独立申请。禁止把企业应用的高权限 token 当作每个员工的业务身份，也不能把第三方 user_access_token 不经适配直接交给智脑 OIDC 验证器。

## 3. 钉钉

### 3.1 需要准备

企业 CorpId、应用 Client ID/Secret、后台配置需要的应用标识、测试成员 userid 与平台账号绑定、手机和 PC 可达的 HTTPS 首页、精确 Origin、可见范围，以及平台要求的权限/出口配置。Secret 只保存在服务端受限文件。

### 3.2 操作步骤

1. 企业管理员创建内部 H5 微应用，先只对测试成员可见。
2. 使用 `apps/dingtalk` 构建，部署到独立 HTTPS 站点，同源代理 `/api`。
3. 配置应用首页和 PC 首页；按照当前后台要求完成可信域名、应用权限及发布设置。钉钉官方示例采用这两个入口配置，并说明发布后可从移动端和 PC 工作台使用。[官方示例](https://github.com/open-dingtalk/h5app-auth-demo)
4. 按 [钉钉专用指南](DINGTALK_INTEGRATION.md) 配置 `DINGTALK_CONFIG_FILE`。若已启用托管身份清单，清单内必须有启用的 `dingtalk`。
5. 用户进入 H5，由宿主取得免登码，API 验证并绑定 IAM。后台选择“管理员可见”只是应用可见范围，不是本项目管理员授权。
6. 先在一个低权限手机账号和 PC 账号上验证，再扩大测试范围。

### 3.3 必测与限制

验证缺少绑定、停用员工、其他企业、验证码重用、用户取消、SDK 超时和重新打开后的账号切换。当前采用 `runtime.permission.requestAuthCode` 及 `dingtalk-jsapi@3.2.9`，不能直接混用另一个同名新版接口。

当前一个部署只配置一个钉钉企业应用；挑战及重放记录为进程内状态，多节点需先迁移到可原子消费的共享存储。H5 没有 Electron 文件执行权限；钉钉消息、审批、钉盘和员工离职事件同步尚未接入。

## 4. 企业微信

当前是接入设计与准备清单，**没有可直接启用的 `wecom` 配置或登录路由**。

### 4.1 需要准备

- 企业 CorpID、自建应用 AgentId/Secret、应用可见成员范围。
- 平台要求的授权回调域、可信域名校验材料和企业可信 IP；地址必须属于本项目，不复制教程中的厂商回调域。
- 经核实的企业成员标识与平台账号绑定，以及测试企业的普通/停用/未绑定账号。

这些准备字段可在腾讯官方的企业微信对接说明中核对；不同产品的回调地址和客户端包标识不能照搬。[腾讯 iOA 对接准备](https://cloud.tencent.com/document/product/1092/128580)；[腾讯 OneID 企业微信认证配置](https://cloud.tencent.cn/document/product/1441/107281)

### 4.2 开发与配置步骤

1. 管理员创建自建应用并设置最小可见范围，保存企业和应用标识。
2. 部署业务 H5 首页；运营端如果需要接入，应使用独立入口及运营可见范围。
3. 开发企业微信宿主：区分企业微信内网页授权与外部浏览器扫码登录，不能把二者的回调参数、SDK 和授权码交换逻辑直接混用。
4. 开发服务端认证适配：生成绑定请求的随机 state/挑战、严格校验回调、一次性消费授权码、服务端验证企业成员身份，然后映射 IAM。
5. 新增配置校验、会话绑定校验、最小公开登录路由、认证限流和客户端协议门禁。路径及字段须在正式实现时确定，本文不提供不存在的接口供调用。
6. 配置真实回调和域名验证，逐端验收后发布。

只接受能够证明属于指定企业的成员身份；无法证明是内部成员的身份结果应拒绝。不得按昵称、手机号后缀或浏览器提交的 userid 自动授权。

### 4.3 验收重点

企业微信手机、PC、外部浏览器扫码分开测试；覆盖可见范围之外成员、回调 state 不一致、授权码重复、外部身份、切换企业和未绑定用户。

如果以后需要接收消息或通讯录事件，再准备对应的回调验证/加密材料和权限。这些不是单纯网页免登必须一次性申请的全量权限。

资料说明：本次无法直接读取企业微信开发站正文，以上准备字段使用腾讯官方集成文档交叉核对；具体自建应用授权 API、scope 和客户端版本须在企业联调前由接入人员核实。本指南不据此宣称已经完成协议或真机验证。

## 5. 飞书（国内版）

当前专用适配待开发，不能把 `type: feishu` 写入现有清单，也不能把钉钉免登 SDK 放入飞书。

### 5.1 需要准备

国内飞书企业自建应用的 App ID/Secret、网页应用主页、实际使用端的入口配置、重定向 URL、测试可见范围，以及经核实的用户 ID 类型和企业归属。密钥仅供服务端读取。

### 5.2 开发与配置步骤

1. 创建自建应用并启用网页能力，按目标端配置首页、发布范围和最小身份权限。
2. 编写飞书宿主，采用官方网页免登流程获取授权码。官方指南使用 `requestAccess`，并提供旧客户端兼容思路；用户拒绝授权不是自动降级登录的理由。[飞书网页应用免登](https://open.feishu.cn/document/client-docs/h5/development-guide/step-3)
3. 由服务端交换合法凭据并获取当前用户身份，核对应用和企业归属；具体交换协议按所选官方接口版本实现，不拼接不同版本示例。[获取用户访问令牌](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token)；[获取用户信息](https://open.feishu.cn/document/server-docs/authentication-management/login-state-management/get)
4. 绑定稳定的外部用户标识与 IAM；在绑定表中明确采用哪种 ID。不要混用 open_id、user_id、union_id，也不要把一个应用的标识当作所有应用通用标识。
5. 将该协议接入统一身份注册和会话验证；前端复用工作台，不复制 Agent 业务逻辑。
6. 发布测试版，手机与 PC 分别验证登录、材料上传、任务及权限。

### 5.3 验收重点

验证拒绝授权、低版本宿主、回调重放、同名员工、错误 ID 类型、切换企业及失效授权。Token 仅用于其授权对象；未经兼容性验证，不把飞书原生 token 当作本项目 JWT Bearer。

如需以用户身份读写云文档、审批或消息，需要额外的资源授权和连接器；免登完成并不等于获得这些权限。业务端接入也不代表元域智营端已具备飞书入口。

## 6. 华为 WeLink

当前专用适配待开发。对现有 Vue 工作台优先评估 H5 轻应用，不先重写成 We码小程序。华为文档将轻应用定义为 H5 方式，适合接入已有 Web 页面。[开发指引](https://support.huaweicloud.com/devg-welink/start.html)

### 6.1 需要准备

企业开发者资格、轻应用 client_id/client_secret、首页、应用可见范围、登录身份接口权限、企业成员绑定及实际目标客户端。华为文档说明服务端凭据从应用基本信息取得，API 权限需按应用申请。[服务端凭据](https://support.huaweicloud.com/devg-welink/start-09.html)；[接口权限申请](https://support.huaweicloud.com/devg-welink/start-10.html)

### 6.2 接入步骤

1. 创建企业轻应用，配置已部署的业务 H5 首页及测试范围。
2. 按轻应用文档开发宿主身份获取及服务端验证，绑定企业/应用/用户；不要直接套用 We码小程序或管理后台免登接口。
3. 接入平台统一会话和 IAM，再测试用户停用、身份源停用及配置变更。
4. 对实际手机和 PC 客户端分别验收，尤其是文件选择、窗口大小和登录接口可用性。

如果企业已经部署华为 OneAccess，可以评估经企业认证服务联邦接入。官方提供 WeLink 工作台免密登录的集成案例，但本项目仍须验证其对本 API 的 Token 类型、issuer、audience 和绑定方式；不能只填写门户链接便宣称已接通。[OneAccess 官方案例](https://support.huaweicloud.com/bestpractice-oneaccess/oneaccess_05_0117.html)

### 6.3 验收重点

账号未授权、接口权限未申请、企业网络不可达、宿主功能不支持时要明确失败；不得回退为 Demo 身份。不要假定 We码、H5、管理后台和 PC 的接口完全一致。

## 7. WPS 365 / WPS 协作

当前专用适配待开发。本节指国内企业协作应用接入，不指给 WPS 文档编辑器安装一个插件就完成智脑集成。

### 7.1 需要准备

企业自建应用 APPID/APPKEY、用户授权回调地址、实际使用的网页入口、权限申请与发布审核、目标企业和成员绑定。应用凭据与用户凭据用途不同，不应混用。[WPS 认证与授权概述](https://open.wps.cn/documents/app-integration-dev/wps365/server/certification-authorization/summary)

### 7.2 接入步骤

1. 创建企业应用，部署工作台，按后台配置入口、安全项和测试范围。
2. 根据宿主能力选择 JSAPI 授权码或网页授权跳转；必须保留用户拒绝和超时分支。官方 `requestAccess` 文档列出 iOS、Android、PC 的支持要求，逐项与目标客户端比对，不只看页面能否加载。[requestAccess](https://open.wps.cn/documents/app-integration-dev/wps365/client/web-jsapi/business/login/requestAccess)
3. 服务端校验 state、交换授权码、取得用户身份并绑定企业账号。官方用户授权流程要求后续敏感令牌操作在服务端完成。[用户授权流程](https://open.wps.cn/documents/app-integration-dev/wps365/server/certification-authorization/user-authorization/flow)
4. 实现专用身份适配、撤销校验及回归。WPS Token 即使看似 JWT，也不能不检查用途就当作本 API 的访问令牌。
5. 根据业务需要再接云文档、文件或消息能力，不用通讯录全量权限来完成最小免登。

服务端令牌接口采用其官方规定的请求格式，不照搬钉钉的 JSON 请求体；刷新及权限范围以当前接口文档为准。[获取用户 access_token](https://open.wps.cn/documents/app-integration-dev/wps365/server/certification-authorization/get-token/get-user-access-token)

### 7.3 验收重点

个人身份与企业身份分开核对，验证其他企业用户、未绑定用户、授权取消、令牌到期、重复回调和文档权限不足。不要把登录时返回的应用身份作为操作所有员工文件的授权。

## 8. 国内统一身份服务：OIDC 路线

如果企业已经建设统一身份中心，可以让国内协同平台接到企业身份中心，再由身份中心向智脑提供受信任的登录结果。本项目不要求必须采购某个厂商。

Authing 官方支持作为 OIDC 身份源，并介绍授权码及授权码 + PKCE；可作为国内接入候选。腾讯 OneID、华为 OneAccess 等场景也应先验证具体产品版本与资源 Token，不因为有“SSO”字样就认定完全兼容。[Authing OIDC 与 PKCE 说明](https://docs.authing.cn/v2/guides/federation/oidc.html)

### 8.1 先确认能否被当前代码接受

- 为本 API 签发的有效访问令牌，有可验证的 JWT 签名、准确 issuer/audience，以及 sub、iat、exp。
- 托管适配器当前采用 RS256/ES256 验证路径；以实际配置和令牌签名为准。不能把 HS256 密钥塞进前端。
- 提供可信 HTTPS JWKS 地址。客户端不能任意提交 issuer/JWKS 供服务端抓取。
- OIDC 有效不代表所有 access_token 都是 JWT。只有 opaque token、仅 SAML/CAS，或缺少本 API audience 时，需要额外适配，不能直接填写配置了事。
- 不用 ID Token 或应用级凭据冒充员工访问令牌；不将登录供应商的示例 Token 贴到线上解码网站。

### 8.2 项目配置

按 [现有模板](../../config/identity-providers.example.json) 准备项目外的 `identity-providers.json`，填写准确 issuer、JWKS、audience、平台 tenantId 与显式 subject 绑定。`type` 使用 `oidc`，`id` 可以是内部约定的 `company-sso`；不要使用未实现的专用 type。

配置 `IDENTITY_PROVIDERS_FILE` 后会关闭 OA/本地 Mock 和 Demo 角色兜底。前端宿主仍需完成登录、回调、续期、登出，并将有效 Token 提供给 SDK；后端通用验证器并不实现这些页面流程。

多身份源默认项、可选外部企业声明与会话隔离详见 [身份适配指南](IDENTITY_PROVIDER_ADAPTERS.md)。目前仍是单企业部署的身份联邦，不是多企业应用市场授权管理。

## 9. 各平台共用的验收与上线顺序

1. 确定企业平台、入口及身份路线，准备材料，不先申请所有资源权限。
2. 用合成数据完成页面、身份、绑定、权限拒绝和模型连通验证。
3. 在目标手机和 PC 真实客户端验证，记录客户端版本、企业应用版本和配置版本。
4. 用普通员工、运营用户、未绑定用户及停用用户分别验收。运营发布动作需要独立权限与确认。
5. 接入确实需要的数据/消息/审批能力，每增加一类权限单独回归。
6. 小范围发布，准备回滚入口和服务端绑定撤销方式，再扩大可见范围。

验收至少覆盖：外部管理员不越权、跨企业拒绝、登录失败不降级、回调不能重放、退出后不展示旧员工数据、弱网不重复执行写入、文件上传受策略约束、平台入口不能执行未经确认的电脑操作。

发生身份问题时优先停用对应身份源/绑定，不能通过开放 Demo 或全员管理员来“恢复业务”。离职后应同时停用平台账号；外部目录事件同步与全局单点注销尚未完成。

## 10. 交付与后续开发清单

| 项目 | 目前可做的事情 | 仍需开发/外部配合 |
| --- | --- | --- |
| 钉钉 | 准备真实应用和成员，在现有代码上联调 | 企业发布、真机验收、多节点挑战存储 |
| 企业微信/飞书/WeLink/WPS | 准备应用、回调、成员和最小权限，按本指南设计宿主 | 专用配置、验码、会话适配、SDK 接入、协议门禁及安全回归 |
| 国内 OIDC | 对兼容发行方配置显式绑定和验证 | 企业宿主登录/续期/注销与目标产品联调 |
| 元域智营平台内入口 | 复用运营工作台和统一身份层 | 独立可见范围、宿主登录及运营权限验收 |
