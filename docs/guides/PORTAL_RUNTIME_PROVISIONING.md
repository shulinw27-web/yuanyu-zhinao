## 当前能做什么

已实现门户租户的开通申请记录、取消、实例预检、并发与超时控制、申请失效及审计。记录沿用门户事务存储，在SQLite部署下可以跨进程保留。尚未实现自动创建业务身份、下发运行权益或正式激活双Agent。

客户中心“概览与开通”已支持空间管理员勾选确认、申请/取消预检，并刷新查看每项结果；普通成员不能读取申请明细。部署人员仍通过CLI执行检查。不得把 `preflight_ready` 当作已开通；所有阶段 `runtimeConnected=false`。测试支付、门户owner或平台管理员身份都不能直接变成企业业务管理员。

## 申请条件与接口

仅当前租户的有效owner/admin可提交，且平台管理员已将该空间审核为 `sandbox_ready`。尚未审核、已暂停、普通成员、其他租户账号、无会话或CSRF不匹配均拒绝。沙箱预检不要求付费，测试支付也不会自动发起申请或授予运行权益。

先通过 `GET /api/portal/me` 获取当前租户版本及会话CSRF，再调用：

```http
POST /api/portal/tenant/provision
Content-Type: application/json
Origin: http://127.0.0.1:15195
X-Portal-Client: web
X-CSRF-Token: <当前会话CSRF>
Cookie: yy_portal=<当前登录会话>
```

```json
{
  "tenantId": "<当前租户ID>",
  "requestId": "<本次申请唯一标识>",
  "expectedVersion": 2,
  "confirmed": true
}
```

版本号取当前值，不固定使用示例的2。请求体不能指定服务URL、密钥、业务角色或任意资源；同一租户、申请人和requestId的重复请求返回原申请，版本参数不一致则拒绝。每个租户最多一条活动申请。版本变更后须新申请ID，不能复活已失效的旧申请。

取消接口为 `POST /api/portal/tenant/provision-cancel`，使用同样的登录、来源及CSRF保护，请求体仅包含 `tenantId` 和 `provisioningId`。取消不删除实例、模型或业务数据。

租户管理者从 `/me` 的对应租户 `provisioning` 字段查看最新记录；普通成员不返回这个字段。结果不包含工作租约、服务URL、密钥或原始外部错误。

## 运维运行预检

部署人员在项目目录中执行一次：

```powershell
node scripts/product-portal-runtime.mjs --check-provisioning <申请ID>
```

使用与门户API相同的 `PORTAL_SQLITE_PATH`；默认路径仍是 `backend/.data/product-portal.db`。使用独立实例时在该进程配置 `SEMANTIC_INSTANCES_FILE`，详情见[语义实例接入](SEMANTIC_TENANT_INSTANCES.md)。CLI只检查已经由门户管理者提交的申请，不接受临时tenantId或地址覆盖，不自行创建申请。

这是一次性本地部署操作，没有开放浏览器调用工作器的接口，没有定时调度或常驻自动开通程序。返回 `preflight_ready` 时退出码0，否则正常输出阻断/已失效状态并退出码2；0也不表示企业运行环境已经激活。当前真实检查器必然保留尚未实现的执行面阻断项。

| 检查 | 当前判断依据 |
| --- | --- |
| `semantic_instance` | 可信租户注册表、受保护实例回执、真实Semantica引擎、SQLite持久化开启、存储健康与有效修订号。只有内存实例不通过 |
| `business_iam` | 阻断：业务IAM尚未完成按门户租户的身份映射及安全隔离，现有统一工作区不能直接复用为租户授权 |
| `runtime_entitlements` | 阻断：商业权益到运行时能力及用量的适配未实现 |
| `runtime_revocation` | 阻断：门户状态变更到业务旧会话、在途任务的撤权未实现 |

## 状态和失效规则

| 状态 | 含义 |
| --- | --- |
| `requested` | 管理者已提交，尚未执行检查 |
| `checking` | 本地工作器持有检查租约 |
| `blocked` | 一项或多项未通过；修复依赖后可再次预检 |
| `preflight_ready` | 检查契约全部通过，不是资源激活；当前仅在注入的测试适配器中出现 |
| `cancelled` | 用户取消；迟到结果丢弃 |
| `superseded` | 租户版本、状态、申请人账号或管理权限变化，旧申请失效 |

检查限时5秒、租约30秒、每个申请最多10次检查；活动租约期间拒绝重复检查，过期后可重试。旧租约结果不能覆盖新结果。这里只读取实例状态，没有在预检中派发建模、付款或外部写操作。

检查结果是 `updatedAt` 时刻的记录，不是持续健康监控；正式资源激活前还必须重新检查部署配置、身份及权限，不能复用旧记录作为永久授权。

租户暂停后再恢复、人员停用后再启用，不会复活旧申请。成员、支付等导致租户版本变化，也会保守地使原申请失效，避免使用过时前提。申请取消、检查开始/完成及触发失效的管理操作记录到门户审计。

**申请失效不等于企业会话撤权已经实现。** 本轮没有为门户用户创建企业会话或写入业务权限。下一阶段仍需租户化IAM、受控主体映射、权益适配、会话/任务撤权和资源激活事务；前置未满足时不得将 `runtimeConnected` 改为true。
