## 2. 漏算多少，为什么

| 指标 | 完整人工基线 | 智脑盲测结果 | 漏掉部分 |
| --- | ---: | ---: | ---: |
| 仓内 | 460 件 | 340 件 | 120 件 |
| 在途 | 60 件 | 40 件 | 20 件 |
| 门店现存 | 190 件 | 130 件 | 60 件 |
| 累计实售 | 290 件 | 190 件 | 100 件 |
| 涉及订单金额 | 6,000 CNY | 4,000 CNY | 2,000 CNY |
| 确认到账 | 5,000 CNY | 3,000 CNY | 2,000 CNY |
| 未核销 | 2,500 CNY | 500 CNY | 2,000 CNY |

漏掉 LOT-N4、LOT-N5 的下游，包括 SHOP-N3、SO-N3 及财务流水。现有计划已经取得 `LOT-N2 → LOT-N4` 的谱系边，但没有递归扩展子批次及重新收集下游数据；24 数据集额度也已耗尽。仅将限制改大不能解决闭包、环、撤销边、重复路径和完成性判定。

财务计算器并没有把 6,000 错减成 4,000，而是缺少 SO-N3 的记录。该区别决定了不能靠调整提示词或改公式来修复全部问题。

## 3. 本轮真实模拟暴露的问题与修复项

| 编号 / 优先级 | 证据与原因 | 建议实现及验收条件 |
| --- | --- | --- |
| SC-01 / P0 | executed 拆合批后代没有完整展开，完整回放失败 | 增加有界、逐跳授权的谱系闭包；有访问集、深度/数量/时限、环与冲突处理。向后传播，不反向扩大其他父批次；完整量必须等于上表 |
| SC-02 / P0 | 用户问完整范围，得到直接范围数字，任务仍称完成 | 将计划覆盖能力、已覆盖边、未展开节点、缺失来源返回结构化状态；有未处理后代时标 partial/incomplete，不把局部完整响应当业务全局完整 |
| SC-03 / P1 | B2/B3/B4 三种问题均重复 9 指标；运行时直接拼接计算文本 | 在受控证据/指标之后增加按当前问题组织的分析步骤，返回事实、风险、证据缺口、责任协作、分阶段建议，保留 command=null；不能用通用建议冒充读取结果 |
| SC-04 / P1 | P1 读到了人员，P2 原会话又说没有编号，P3 补传恢复 | 持久材料按对象/主键/字段检索，追问时按授权重新取需要的片段；不要只保留前部摘录，也不能靠先前模型答复重建事实 |
| SC-05 / P1 | B5 没有实际对比两个原料，当前执行只支持单根 | 支持有界多根比较与来源/租户命名空间；验证供应商重号不合并，分别给采购/检验/实际领料证据，拒绝历史权限扩张 |
| SC-06 / P1 | 初轮完整材料出现 `MODEL_RESULT_UNAVAILABLE_OUTPUT_SAFETY`，无具体稳定诊断；简短回答对照成功 | 为内部审计保留非敏感输出校验类别、长度/契约等诊断；不绕过安全检查、不重复业务动作。受控拆分长答案后回归，不能仅扩大 token 并宣布解决 |

SC-03 同时覆盖人员有效性和责任语义：需展示 active 指派、在职状态、证据来源；不能把联系人当事故责任人。当前材料推理已理解该边界，但发布消费回答未实现。

本轮是验证任务，以上产品修复项尚未实施；后续应按 SC-01/02 → SC-03 → SC-04/05 → SC-06 顺序开发并重跑同一材料与独立基线。不要以减小场景、重复上传全套材料或更换正确答案掩盖缺口。
