## 第一阶段实施

模型页不再把校对工作区整体藏在高级区域。共享关系图与字段表单直接绑定同一个 `localDraft`；旧的独立16节点关系预览已移除，减少重复状态。保存、校验、模拟构建与登记保持可见，技术区域默认折叠。点击对象后可以打开对象配置；点击关系可修改名称、基数与依据说明，修改仍只是本次草稿。

撤销和重做不执行请求，不改变服务器草稿或已发布模型。不保存跨刷新编辑历史；角色、资料客户端、服务端草稿变化时清空历史并提示。历史不能复活旧身份下的内容。向 Agent 提问前如有未保存修改，先提示保存，不切换页面让 Agent 用旧修订解释新图。

本地缺失字段及悬空关系可定位处理；服务端校验没有给出对象编码时，只打开校验详情，不根据错误文案猜目标。旧校验结果仍受未保存修改门禁限制。发布仍沿用服务器权限与校验关口。

自动布局先求强连通分量，再布局有向无环的分量图。环路不产生无限遍历，孤立对象保留，不新增或删除任何语义边。同端点多条关系使用不同曲线与标签位置；尚不承诺任意复杂图无交叉或无重叠。

## 第二阶段实施与回归

四类方案包均是合成材料，每包3个系统、3份材料、4条分叉记录和2个验收问题。显式交给 Agent 后仍是候选任务，不配置凭据或授予权限。自动测试验证材料、图投影及权限边界；没有把这四包宣称为真实大模型双 Agent 全链路效果测试。

资料关联的模型分析复用既有知识问答安全管线：管理员 `KNOWLEDGE_MODEL_ALLOWED_MODES` 策略、提供方/模型一致的同意、引用和权限调用前后重验、服务器回填引用片段。模型只能从有界目标目录选择对象或关系；编造目标及非法契约失败，不降级冒充成功。默认明确名称匹配不变。目录超过2700字符拒绝本轮模型分析，建议缩小模型范围；这是首版限制，不截掉目标后假称完整分析。

## 第四阶段：复杂图显示与映射绕过修复（2026-10-09）

关系图改为每次布局统一索引并行边，正反向关系与多个自关联分别使用不同曲线。文字按有界候选位置避让对象和其他文字；没有空位时仅收起文字，保留可点击、键盘可选的连线、完整提示及详情。顶部视口包含自关联曲线，避免负坐标裁切。新增来源系统概览按钮，标明多来源对象重复计数；按钮只是筛选，不把来源系统合并为业务对象，也不增加推断关系。业务域折叠、全局连线避障和超大图性能验收仍未完成。

核查发现主数据映射存在绕过路径：语义关系声明 `keyMapping` 后虽不投影业务边，但同字段对仍可能通过 `reference_*` 外键边显示，读取计划也可能使用等值外键连接。现已对映射覆盖的字段对双向禁止此等值关联，其他谓词不能绕过；定义缺少字段时保守禁止对应类型对。依赖该映射的普通连接及图扩展校验返回 `READ_MAPPING_EXECUTION_REQUIRED`，执行入口以 `READ_PLAN_INVALID` 拒绝，查询次数为0。独立、未受该映射约束的字段关联不受影响。

这只是失败关闭与显示真实性修复，不是主数据映射执行完成。现有 `lookupSource` 是来源说明，不能作为可直接访问的URL或数据库表名；`owner`、`version` 也不代表运行时授权。后续执行能力需明确受控连接器中的映射对象、字段、确认状态、版本和有效期，取得租户/组织/字段授权后读取对照行；拒绝未确认、一对多冲突、过期和缺失映射，并通过与模型指纹和快照绑定的证据生成结果。未完成上述契约与回放前，禁止用字符串相等冒充转换成功。

## 第五阶段：版本化主数据映射执行闭环（2026-10-09）

在第四阶段失败关闭基础上，读取计划新增显式 `where.mapping` 绑定。首版只支持已声明方向的 `master_data_lookup`：对照对象必须单来源，`lookupSource` 必须是其模型编码，两端引用字段必须精确对应业务关系，确认/版本/有效期字段均须声明。方案显式固定UTC有效时点，不默认实时。只有唯一、确认、版本一致且有效的对照行才能转换目标查询值，缺失或重复均失败；逆向转换、规则脚本和递归转换仍不支持。

首次查询前预检包括对照对象在内的所有授权，映射行经过既有租户/组织/来源/分级/字段准入，查询及返回前重验。沿用64次查询、500条记录、60秒等预算，映射业务对最多2000对。执行后生成本进程映射凭据，绑定模型内容及授权记录快照；智脑生成实例图前仍重验权限和发布版本。凭据不能经JSON重建，不能在变更模型或变更记录后复用，不作为持久授权或审批回执。图新增确认映射状态、映射版本和有效时点。

发布链路测试发现原草稿净化会丢失 `keyMapping`，已经修复：合法定义保留，非法定义/不存在的端点字段拒绝，不改变原草稿。净化枚举与限制提取为共用纯契约，身份提案和治理保存复用，没有放宽架构基线。回放增加映射缺失、冲突、过期、未确认、版本/时间错误及目标缺失反例，仍需每个方案正反例通过才能发布。
