## 3. 接口使用

统一前缀 `/api/agent/knowledge-library`，沿用现有认证会话或 Bearer 身份。不要把真实令牌写入文档、源码或测试数据。读取受 `page.agent.view` 保护，保存、预览和撤回需 `agent.prompt.run`。此处保存仅限个人资料，不表示拥有发布企业制度或语义模型的权限。

| 方法及相对路径 | 用途 |
| --- | --- |
| `GET` 前缀本身（无尾斜杠） | 当前身份的文档元数据及可用状态 |
| `POST /preview` | 安全扫描并预览文本分块，不持久化 |
| `PUT /documents/{documentId}` | 显式创建或更新，必须提供预期修订号 |
| `GET /search?query=...&limit=5` | 检索当前有效最新修订，每文档最多一个片段 |
| `GET /documents/{documentId}?revision=1` | 再校验修订和有效期后读取原文 |
| `POST /documents/{documentId}/retract` | 撤回并新增无正文墓碑修订 |

创建请求示例（合成资料）：

```json
{
  "expectedRevision": 0,
  "title": "供应商资质复核",
  "source": "测试制度材料",
  "sourceVersion": "v1",
  "kind": "policy",
  "text": "采购前必须核验供应商资质和质量认证，有效期届满需重新审核。",
  "effectiveFrom": null,
  "effectiveUntil": null
}
```

`documentId` 允许字母、数字、下划线、点和连字符，最长 100 字符。企业、用户、角色不能由请求体指定，额外 ACL 字段被拒绝。`kind` 为 `policy` 或 `reference`，两者都是不可信文档资料，不是实时业务事实。

预览示例：`{"text":"采购前核验供应商资质。","chunkSize":1000}`。保存使用固定 1000 字符分块；预览的自定义大小不会自动改变保存配置。返回的 `start/end` 是原始文本 UTF-16 偏移，左闭右开，不是页码或图片坐标。

更新时提交已读取的当前 `expectedRevision`。冲突返回 409，应重新读取并审阅，不自动覆盖。同修订同内容提交返回 `unchanged`，不重复写审计事件。

撤回请求：`{"expectedRevision":1}`。首次撤回生成修订 2，旧修订不能被检索或打开。对修订 2 再次撤回无变更，对修订 1 重放返回 409。撤回保留历史数据，不是物理删除；恢复需要当前修订和剩余配额。

### 有效期、配额与安全边界

- 有效时间采用严格 UTC 格式，如 `2026-09-12T00:00:00.000Z`，区间左闭右开。
- 仅检索最新修订。未来生效修订替换现有资料后，旧版不会继续服务；需要并存发布策略时，不要提前替换线上有效资料。
- 单文档最多 120,000 字符；每作用域 64 文档、每文档通常 10 修订；工作区序列化预算 2MiB，包含正文、分块和历史，不等于原文件大小。
- 超限保存原子拒绝，不截断、不覆盖。满额仍允许一个无正文撤回墓碑，保留修订数可能达到 11；重复撤回不无限追加记录。
- 作用域来自企业、主体、原始角色的结构化摘要，避免分隔符拼接碰撞。Demo 角色头必须携带设备身份；Demo 不是生产认证方案。
- 无共享、历史正文读取或缓存层；来源标记及知识类型不会扩大权限。
- 检索返回 `document_reference_not_live_business_fact`，并明确标记向量和重排未配置。

| 状态码 | 处理含义 |
| --- | --- |
| 400 | 入参、时间或额外字段不合法，或材料被安全扫描拒绝 |
| 401 / 403 | 会话、身份或权限不满足；不能改请求体角色绕过 |
| 404 | 不存在、不可见、旧修订、撤回或不在有效期，不暴露其他主体资料细节 |
| 409 | 修订冲突，重新读取后处理 |
| 413 | 文档、修订或工作区预算超限，未截断写入 |

## 4. 发现并修复的问题

1. 原 COA 检索对多个业务编号采用“匹配任意一个”，可能把单批次 COA 用于多个批次的问题。升级路径要求匹配全部编号，仍允许通用制度检索，不用默认批次补齐其他目标。
2. 撤回不推进修订号会允许旧客户端重新保存并激活资料。改为墓碑修订，旧写入拒绝，配额满也允许撤回。

两项均有回归。旧检索函数保留原行为，仅供评测；运行时使用新的 `retrieveEnterpriseKnowledge`，不能将基线函数重新接入业务路径。

### 7.2 使用方式

两个前缀均支持第 3 节的六个资料操作，以及上述三个新操作。认证继续使用本项目会话或 Bearer；不是 WeKnora 登录凭证，不要把方舟 Key 交给客户端。

```http
POST /api/semantic-operations/knowledge-library/brief
Content-Type: application/json

{"query":"采购前需要核验哪些供应商资质？","limit":3}
```

结果为 `knowledge-brief.v1`，`mode=extractive_no_llm`；有依据时 `status=evidence_ready`，没有依据时 `status=no_evidence`。`evidence[].excerpt` 是原文，`evidence[].citation` 可原样提交至任一有权限端的 `/citation` 再次打开。不因另一个端读取而发布为企业制度。

- `query` 最长 4000 字符，`limit` 为 1–5；证据正文合计最多 16000 字符，超限返回 413，不截断凑答案。
- 资料在复核期间更新或撤回时，`/brief` 返回 409 `KNOWLEDGE_EVIDENCE_CHANGED`，不返回部分摘录。客户端应重新检索并让用户重新核对。
- 摘录返回前再次检查权限；被拒绝返回 403，不附带已读正文。外部异常不回传上游错误正文或凭证。
- 本地定位是 UTF-16 文本偏移；外部适配器只声明分块 ID，不伪装成 PDF 页码或图像位置。
- 没有自动加入聊天历史、缓存或流式正文。后续生成模型接入必须另做生成前后、旧对话引用复核，不能直接复用旧答案。

本轮未增加前端组件，也未重启正在使用的服务；新接口需下次启动更新后的 Node API 才可使用。

### 7.3 WeKnora 适配器启用前提

服务端工厂 `createWeKnoraKnowledgeProvider` 不从客户端或环境变量自动启用，后续组合时需要：

1. 本机地址，限定 `http://127.0.0.1:<port>`；拒绝凭据、额外路径、查询参数和非回环主机，不是通用远程连接器。
2. WeKnora 自身最小只读 API Key 及指定资料读取权限；方舟 Key 不能代替。本轮未创建新 Key。
3. 服务端 `resolveScope`，按当前企业、主体、原始角色返回绑定：`principalKey=knowledgePrincipalKey(context)`、WeKnora `tenantId`、单个 `knowledgeBaseId`、1–32 个明确 `knowledgeIds`。无绑定、主体不符或空清单时，不发起请求，不默认全库检索。

使用 `/api/v1/knowledge-bases/{id}/hybrid-search`，强制传文档白名单、关闭向量和上下文扩展，再通过 `/knowledge/{id}` 与 `/chunks/by-id/{id}` 读权威内容。搜索片段和 URL 不直接用作依据。校验空间/知识库/文档归属、启用/解析/索引状态、更新时间和内容指纹；绑定撤销或文档变化即失效。显式业务编号必须全部匹配。

每次 HTTP 请求默认 2 秒超时（可配置 10–10000 毫秒），响应上限 256KiB；不重定向、不自动重试、不回传上游错误正文。最多返回 5 条，只支持已索引文本分块，不支持 FAQ、图片块、全文下载或企业共享 ACL 自动映射。没有转发第三方完整问答结果。

HTTP 调用间复核不是分布式事务，不能保证最后一次检查后任何时刻都不发生撤权。生产异步 IAM 请求内快照、会话注销、中途撤权信号和分布式缓存仍需专项集成验证，不宣称关闭全部生产动态授权待办。
