## 当前交付：第七批（2026-09-13）

补齐“元域智语发布多个方案 → 业务用户选一个 → 联合核验”的显式流程。没有增加自动制度适用性判断或自动业务执行。

- `GET /api/agent/knowledge-library/joint-plans` 返回当前身份可访问的发布版本、24位模型指纹、方案名称、根对象类型与输出。仅元数据，不读业务；匿名拒绝，语义端无此接口。读取发布模型后再次检查元数据授权。
- 模型服务和运营人工导入均支持1–3个不同编号的读取方案。每个方案须通过正例和反例回放，不能只验一个便发布整个模型。每轮仅执行选中方案，未知方案、多方案未选定时不查询连接器。
- 业务页展示目录和口径信息；唯一方案可预选，多个方案必须选择，再填明确编号并单次确认。没有可访问模型/方案时直接提示准备事项并禁用确认和提交，不等查询后才报错。
- 界面提交发布版本与指纹；模型变更时在读取业务前拒绝。刷新目录、改变问题/编号/方案或来源会清除旧结果与确认。结果保留实际选中的方案标识，避免混淆两种计算口径。
- 单方案旧调用兼容省略 `planId`。主聊天当前没有多方案选择控件，不会自动猜选；需要多个方案时走知识资料页的联合核验入口。这一限制仍在后续自动规划范围。

本轮发现并修复了服务端及运营导入的单方案限制；集成测试还发现新增请求校验误用了64位知识摘要规则，已改为项目真实的24位语义模型指纹，并用正式发布流程生成的指纹验证。

验证记录：知识专项51/51；读取运行时12/12，包含双方案逐项正反例回放、不同授信口径和实际选中方案的联合读取；运营导入2/2。全量 `npm run quality`、四端前端构建、凭据扫描与文档链接检查通过。正式发布集成使用真实校验/回放/读取代码，连接器与 Semantica 发布回执是合成测试桩，不是新的生产部署验收。

真实 HTTP 测试：`npm run evaluate:weknora -- --live-synthetic` 13/13，通过双端原文检索/引用复验/越权拒绝及新增目录身份隔离检查，未调用模型、未写上游。首轮 Docker 引擎未运行导致两端503；恢复已安装 Docker 和原容器后通过，未更改 Key、ACL 或数据库。浏览器在隔离内存 API 下验证了真实原文已检索、无发布方案前置禁用及刷新后仍禁用；截图检查没有表单重叠。多方案成功计算由后端发布集成测试覆盖，尚未完成浏览器导入、发布、选择到成功计算的全流程。

仍待完成：自然语言选制度/方案、有界补查和模型联合解释；企业共享同步与保留删除治理；真实企业身份撤权、多模态区域到候选模型连线、独立盲测和生产负载。上述功能不因本批通过而标为完成。

## 历史交付：第六批（2026-09-13）

在第五批真实接入基础上，增加业务端“知识依据＋业务事实”只读联合核验。它是来源分离的核验流程，不是模型自由联合推理，不自动替用户选择制度、编号或处置方案。

- 新接口 `POST /api/agent/knowledge-library/joint-brief`：明确确认、最多3个不重复根对象、当前来源引用；严格请求字段，拒绝“不要读取业务数据”等相反指令。元域智语端不开放此接口，也不显示按钮。
- 使用现有已发布读取计划、逐对象 IAM 和连接器；在此流程显式关闭模型分析。资料原文与计算事实分别返回，不复制业务 payload，不将制度变成执行授权。
- 读取两次声明图，比较记录、结果和覆盖范围；资料在阶段间重复复验，最后核验模型版本、对象授权和页面/按钮权限。变化或不完整则拒绝整个结果。并非跨系统原子事务，不能承诺多个外部系统的同一时刻快照。
- 界面要求先检索依据，输入问题与明确编号，然后单次确认；显示业务计算、资料原文、覆盖范围和限制。刷新来源/问题会清除旧结果与确认。
- 专项新增4条服务测试：确认/输入范围、无发布模型、业务数据变化、资料撤回、模型轮换和末端对象撤权；在现有正式发布/回放测试中接入18对象跨渠道订单场景，使用真实读取代数和模拟连接器验证库存/授信结果，不用桩业务结果替代该集成断言。

验证：`npm run quality` 通过，知识专项49/49；智脑、语义、移动及钉钉前端构建通过。浏览器在内存 API 下读取真实 WeKnora 合成原文，确认按钮门禁、无发布模型时拒绝；运营端知识页没有联合业务读取控件。成功计算路径由已发布模型集成测试覆盖，尚未在浏览器中发布该场景并完成成功路径。未调用额外模型，未改真实业务数据。

回归中有一次专项出现瞬时503，立即复跑通过；已将本地 HTTP 桩的 `Connection: close` 从成功分支扩展至错误/重定向分支，避免测试连接池复用已关闭端口。之后连续5轮提供方测试通过。这是稳定性防护，不将单次现象唯一归因已证实，也未给生产请求增加自动重试。

仍未关闭：自然语言自动选择适用制度/读取方案、有界补查及模型联合解释；企业共享同步/删除治理、真实IAM撤权、区域级多模态模型连线、独立盲测和生产负载。只关闭“明确输入的只读并列核验”子项，不把它标为 WK-04 整项完成。

- 修正混合检索仍标记关键词、摘录接口固定标记“未使用向量”的诊断。混合模式报告 `provider_requested_not_attested`：请求了提供方向量能力，但不冒称已核验远端每次内部执行。

### 实现与实际修复

- 两端资料页新增模型问答：每轮显式选择来源，保留最近 6 个用户问题（总计最多 6000 字符），不回填旧模型答案。最多 5 个引用、16000 字符证据；模型单次 45 秒上限。服务端许可和用户本次模型确认缺一不可。
- 新增 `KNOWLEDGE_MODEL_ALLOWED_MODES`，默认空，即拒绝个人知识出网。确认绑定当前 provider/model；调用前后重新核验权限、模型策略和全部来源。此配置不改变原有业务聊天，也不替代企业数据分级审批。
- 真实调用发现四个问答均因引用校验失败被拒绝。诊断确认：网关 NFKC 规范化改变全角逗号、冒号，而直接引文匹配原始文本。改为模型只选择来源与片段编号，由服务端回填原文；没有降低原文有效性、授权或引用存在性要求。
- Wiki 支持模型整理和本地来源提纲两种模式，界面明确区分。模型草稿先进入人工校对，再显式保存；不自动创建正式模型。规则提示仅比较同名“字段：值”，差异不自动裁决；未命中不表示一致。
- Wiki 保留最近 10 个旧修订。打开历史也复验来源；恢复需要确认和 CAS，新增修订，不覆盖历史。响应只返回历史元数据，不能通过当前版偷读旧版笔记。
- 多模态复用现有受控解析器，无第二套文件存储。页面展示本地原图/PDF、解析文本和人工修正；Office/结构化文件不伪装成原版页面。修正结果先转资料编辑框，确认后作为人工参考资料保存，原文件不变。
- 修复 Office、CSV/JSON/YAML 被错误标为“第 1 页”：PDF 才返回真实页码；Excel 标为工作表/单元格文本，Word 标为段落/表格文本。不造图像区域或单元格像素坐标。
- 增加当前身份绑定指纹和仓库外配置助手 `scripts/save-weknora-config.ps1`。隐藏输入专用 WeKnora Key、检查私有目录 ACL、拒绝覆盖已有文件；默认关键词，不自动开启向量调用。助手已完成语法检查，尚未输入真实 Key 运行。

## 3. 接口使用

统一前缀 `/api/agent/knowledge-library`，沿用现有认证会话或 Bearer 身份。不要把真实令牌写入文档、源码或测试数据。读取受 `page.agent.view` 保护，保存、预览和撤回需 `agent.prompt.run`。此处保存仅限个人资料，不表示拥有发布企业制度或语义模型的权限。

| 方法及相对路径 | 用途 |
| --- | --- |
| `GET` 前缀本身（无尾斜杠） | 当前身份的文档元数据及可用状态 |
| `POST /preview` | 安全扫描并预览文本分块，不持久化 |
| `PUT /documents/{documentId}` | 显式创建或更新，必须提供预期修订号 |
| `GET /search?query=...&limit=5` | 检索当前有效最新修订，每文档最多一个片段 |
| `GET /documents/{documentId}?revision=1` | 再校验修订和有效期后读取原文 |
| `POST /documents/{documentId}/retract` | 撤回并新增无正文墓碑修订 |

创建请求示例（合成资料）：

```json
{
  "expectedRevision": 0,
  "title": "供应商资质复核",
  "source": "测试制度材料",
  "sourceVersion": "v1",
  "kind": "policy",
  "text": "采购前必须核验供应商资质和质量认证，有效期届满需重新审核。",
  "effectiveFrom": null,
  "effectiveUntil": null
}
```

`documentId` 允许字母、数字、下划线、点和连字符，最长 100 字符。企业、用户、角色不能由请求体指定，额外 ACL 字段被拒绝。`kind` 为 `policy` 或 `reference`，两者都是不可信文档资料，不是实时业务事实。

预览示例：`{"text":"采购前核验供应商资质。","chunkSize":1000}`。保存使用固定 1000 字符分块；预览的自定义大小不会自动改变保存配置。返回的 `start/end` 是原始文本 UTF-16 偏移，左闭右开，不是页码或图片坐标。

更新时提交已读取的当前 `expectedRevision`。冲突返回 409，应重新读取并审阅，不自动覆盖。同修订同内容提交返回 `unchanged`，不重复写审计事件。

撤回请求：`{"expectedRevision":1}`。首次撤回生成修订 2，旧修订不能被检索或打开。对修订 2 再次撤回无变更，对修订 1 重放返回 409。撤回保留历史数据，不是物理删除；恢复需要当前修订和剩余配额。

### 有效期、配额与安全边界

- 有效时间采用严格 UTC 格式，如 `2026-09-12T00:00:00.000Z`，区间左闭右开。
- 仅检索最新修订。未来生效修订替换现有资料后，旧版不会继续服务；需要并存发布策略时，不要提前替换线上有效资料。
- 单文档最多 120,000 字符；每作用域 64 文档、每文档通常 10 修订；工作区序列化预算 2MiB，包含正文、分块和历史，不等于原文件大小。
- 超限保存原子拒绝，不截断、不覆盖。满额仍允许一个无正文撤回墓碑，保留修订数可能达到 11；重复撤回不无限追加记录。
- 作用域来自企业、主体、原始角色的结构化摘要，避免分隔符拼接碰撞。Demo 角色头必须携带设备身份；Demo 不是生产认证方案。
- 无共享、历史正文读取或缓存层；来源标记及知识类型不会扩大权限。
- 检索返回 `document_reference_not_live_business_fact`，并明确标记向量和重排未配置。

| 状态码 | 处理含义 |
| --- | --- |
| 400 | 入参、时间或额外字段不合法，或材料被安全扫描拒绝 |
| 401 / 403 | 会话、身份或权限不满足；不能改请求体角色绕过 |
| 404 | 不存在、不可见、旧修订、撤回或不在有效期，不暴露其他主体资料细节 |
| 409 | 修订冲突，重新读取后处理 |
| 413 | 文档、修订或工作区预算超限，未截断写入 |

## 4. 发现并修复的问题

1. 原 COA 检索对多个业务编号采用“匹配任意一个”，可能把单批次 COA 用于多个批次的问题。升级路径要求匹配全部编号，仍允许通用制度检索，不用默认批次补齐其他目标。
2. 撤回不推进修订号会允许旧客户端重新保存并激活资料。改为墓碑修订，旧写入拒绝，配额满也允许撤回。

两项均有回归。旧检索函数保留原行为，仅供评测；运行时使用新的 `retrieveEnterpriseKnowledge`，不能将基线函数重新接入业务路径。

### 7.2 使用方式

两个前缀均支持第 3 节的六个资料操作，以及上述三个新操作。认证继续使用本项目会话或 Bearer；不是 WeKnora 登录凭证，不要把方舟 Key 交给客户端。

```http
POST /api/semantic-operations/knowledge-library/brief
Content-Type: application/json

{"query":"采购前需要核验哪些供应商资质？","limit":3}
```

结果为 `knowledge-brief.v1`，`mode=extractive_no_llm`；有依据时 `status=evidence_ready`，没有依据时 `status=no_evidence`。`evidence[].excerpt` 是原文，`evidence[].citation` 可原样提交至任一有权限端的 `/citation` 再次打开。不因另一个端读取而发布为企业制度。

- `query` 最长 4000 字符，`limit` 为 1–5；证据正文合计最多 16000 字符，超限返回 413，不截断凑答案。
- 资料在复核期间更新或撤回时，`/brief` 返回 409 `KNOWLEDGE_EVIDENCE_CHANGED`，不返回部分摘录。客户端应重新检索并让用户重新核对。
- 摘录返回前再次检查权限；被拒绝返回 403，不附带已读正文。外部异常不回传上游错误正文或凭证。
- 本地定位是 UTF-16 文本偏移；外部适配器只声明分块 ID，不伪装成 PDF 页码或图像位置。
- 没有自动加入聊天历史、缓存或流式正文。后续生成模型接入必须另做生成前后、旧对话引用复核，不能直接复用旧答案。

本轮未增加前端组件，也未重启正在使用的服务；新接口需下次启动更新后的 Node API 才可使用。

### 7.3 WeKnora 适配器启用前提

服务端工厂 `createWeKnoraKnowledgeProvider` 不从客户端或环境变量自动启用，后续组合时需要：

1. 本机地址，限定 `http://127.0.0.1:<port>`；拒绝凭据、额外路径、查询参数和非回环主机，不是通用远程连接器。
2. WeKnora 自身最小只读 API Key 及指定资料读取权限；方舟 Key 不能代替。本轮未创建新 Key。
3. 服务端 `resolveScope`，按当前企业、主体、原始角色返回绑定：`principalKey=knowledgePrincipalKey(context)`、WeKnora `tenantId`、单个 `knowledgeBaseId`、1–32 个明确 `knowledgeIds`。无绑定、主体不符或空清单时，不发起请求，不默认全库检索。

使用 `/api/v1/knowledge-bases/{id}/hybrid-search`，强制传文档白名单、关闭向量和上下文扩展，再通过 `/knowledge/{id}` 与 `/chunks/by-id/{id}` 读权威内容。搜索片段和 URL 不直接用作依据。校验空间/知识库/文档归属、启用/解析/索引状态、更新时间和内容指纹；绑定撤销或文档变化即失效。显式业务编号必须全部匹配。

每次 HTTP 请求默认 2 秒超时（可配置 10–10000 毫秒），响应上限 256KiB；不重定向、不自动重试、不回传上游错误正文。最多返回 5 条，只支持已索引文本分块，不支持 FAQ、图片块、全文下载或企业共享 ACL 自动映射。没有转发第三方完整问答结果。

HTTP 调用间复核不是分布式事务，不能保证最后一次检查后任何时刻都不发生撤权。生产异步 IAM 请求内快照、会话注销、中途撤权信号和分布式缓存仍需专项集成验证，不宣称关闭全部生产动态授权待办。
