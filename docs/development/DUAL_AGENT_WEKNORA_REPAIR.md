## 2. 修复中再次发现的问题

单独审批问答在检索正确后仍发生失败。新增诊断定位到 `unauthorized_execution_claim`：对 JSON 整体做正则匹配，可能将一个字符串末尾的“已执行”和另一个字符串中的“OA”拼接成并不存在的执行声明；明确的“不等于已执行”也可能误报。

现按结构化答案各字符串分别检查执行声明，并在句内识别限定的否定表达。否定不能跨逗号、分号或转折词吞掉后一条声明。“不代表已执行然而我已经提交采购订单”仍拒绝；凭据、提示注入和未知字段检查保留。这是已复现误报的修复，不是任意自然语言声明的完整证明器。

读取方案首版让模型同时产生关联别名与公式，真实调用出现 `READ_OPERATOR_UNKNOWN`、`READ_FIELD_SCOPE`。未保存这些结果。改为服务器编译声明外键图、固定别名等于对象类型，模型只能引用目录生成表达式。运行时仍做字段、作用域、算子、深度及回放检查。

## 4. 如何使用

### 智脑和语义端的资料追问

1. 在知识资料页检索并查看依据，输入具体追问。
2. 依据不足时点击“在所选文档内补查并预览”。例如输入 `execution_receipt_id` 或货权转移问题。
3. 展开补查片段，核验来源。新片段替换本轮问答引用，不修改知识库原文。
4. 重新勾选模型发送确认，再回答或生成 Wiki。补查失败不会使用旧结果冒充新依据。

### 元域智语的读取方案

1. 进入人工校对，先保存模型结构与规则。
2. 展开“智脑关联查询与计算”，选择业务根对象，填写需要核验的指标、公式、过滤条件和单位换算。
3. 确认有权发送已保存的模型结构、规则及诉求，点击“生成只读方案预览”。不发送原始业务记录。
4. 检查关联链和每个表达式，再采用到未保存草稿。已有判断绑定不会被自动删除；更改草稿、权限或模型后不能使用旧提案。
5. 保存、校验，对每个方案运行正例与反例，构建并发布。只有此后智脑才能使用它。

目录最多 24 个数据集，每类对象只选一条已声明关联路径，不自动展开任意循环或推断因果。多个外键或非后代节点的替代路径须人工选择，界面不默认采用，选择后必须重新确认。同类对象同时承担收货客户、结算客户等角色时，仍需人工多别名方案。复杂九指标、跨时间状态或多路径业务仍需独立回放。自然语言生成不能代替审核。
