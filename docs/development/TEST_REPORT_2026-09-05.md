## 8. 发现项与风险

### R01：缺少可追溯的版本基线（高）

当前项目目录没有 Git 元数据，测试结果无法绑定到不可变提交。代码被修改后，本报告仍可能被误认为有效。

**建议：** 建立 Git 仓库和发布标签；每次测试报告记录 commit SHA、依赖锁文件校验值和构建产物校验值。

### R02：真实企业集成未验收（高）

现有自动化主要使用内存、模拟仓储和 Mock 连接器。OA、ERP、WMS、MES、LIMS、QMS、OMS 以及生产身份、数据库、消息中间件和密钥中心尚未在真实拓扑中验证。

**建议：** 先建立联调环境与脱敏测试账号，再按系统逐项完成连通、鉴权、字段映射、幂等、超时重试、补偿、审计和数据对账。

### R03：许可证元数据不完整（中）

567 个第三方包中没有发现 AGPL/SSPL 等当前规则禁止的许可证，但有 93 个包未能自动识别许可证。未知不等于违规，也不能视为已经合规。

**建议：** 对未知项按直接依赖、生产传递依赖、开发依赖分层复核，并保留许可证文本和法务结论。

### R04：非功能数据不足以支持容量结论（高）

本轮负载测试只覆盖健康接口，稳定性抽样只有 10 秒，没有真实数据库、模型推理和外部连接器开销。

**建议：** 在联调环境补充核心对话、语义建模、权限查询、任务编排和桌面派发链路的阶梯压测，并执行至少 72 小时稳定性测试。

### R05：真实模型与桌面操作未做人工闭环（高）

本轮回归覆盖模型治理和桌面执行代码，但没有使用真实模型完成多轮对话、文件生成、电脑操作、暂停/确认/恢复和审计回放的人工验收。

**建议：** 建立固定验收脚本和测试账号，逐项录屏并保存 Trace ID、确认记录、输出文件和失败恢复证据。
