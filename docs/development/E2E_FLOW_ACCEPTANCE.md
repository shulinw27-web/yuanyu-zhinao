# 双 Agent 全流程 E2E：安全运行与验收口径

更新：2026-10-07。

## 运行边界

`scripts/e2e-normal-flow.mjs` 会提交接入系统、材料、巡检计划和会话，**还会保存并发布固定的 `oa-governance` 模型**。因此它不是只读脚本，也不能对当前共享演示实例、已有租户或生产环境执行。

推荐直接运行项目提供的一次性隔离编排器：

```powershell
npm run evaluate:e2e-isolated
```

编排器会分配隔离端口和运行时数据库，启动 API、Semantica、巡检 Worker 与合成 OMS 连接器，结束时回收所启动的进程。原始脚本仍可供高级调试使用：`npm run e2e:flow -- --isolated-runtime --base http://127.0.0.1:<隔离端口>/api`。无 `--isolated-runtime` 或非本机 HTTP 地址会在发出请求前拒绝；手工使用该标志时，它只是操作者的隔离声明，**不是服务端隔离证明**。任务容量已满时脚本直接失败，不再归档任何已有会话。结果写入 `output/e2e-normal-flow/report.json`。

## 验收口径

脚本分认证、系统接入、材料提交、建模、发布、巡检、智脑七段。最后一段现要求智脑回复同时满足：没有业务写入命令、走 `controlled_semantic_read`、使用本轮发布的模型版本、返回可复核来源证据。仅 HTTP 200、字段齐全或回答非空不再算双 Agent 闭环成功。

当前合成场景已声明 OMS 订单读取方案、对象授权与条件授权，先执行允许／拒绝两条回放，再发布同一模型版本；智脑随后只读查询 `ORD-E2E-001`，核对订单金额 **33,000 CNY** 与延期标志，并要求返回同版本来源证据。2026-10-07 本机隔离执行结果为 **44/44 通过、0 失败、53 次 HTTP 请求**。这证明的是受控合成数据上的确定性链路，不代表真实企业连接器、生产权限目录或真实模型质量已经验收。

`npm run quality` 不运行本 E2E，也不运行付费／真实云模型评测；两者应分别报告，不能互相替代。
