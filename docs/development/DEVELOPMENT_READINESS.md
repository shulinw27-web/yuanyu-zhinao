# 真实开发与系统联调准备事项

更新：2026-09-17。本文列未来真实企业接入所需的材料、工具和环境，不列人员 Owner，也不替代上线检查表。

当前没有可供验证的真实企业场景，近期以 [Mock 优先的开发路线](DEVELOPMENT_ROADMAP.md) 为准。下面的接口文档、字典、样本和业务规则先用合成材料准备，网络、账号和权限用隔离本地模拟环境验证；真实凭据、企业网络和客户验收不作为本阶段开发前置条件，也不得据 Mock 通过标记已完成。真实环境到位后，再逐项替换核验。

## 1. 每个待接系统需要提供的材料

适用于 OA、ERP、WMS、MES、LIMS、QMS、OMS 等系统；企业内部名称不同的，先确认其实际职责和接口，不按缩写猜测。

| 材料 | 最少要包含什么 |
| --- | --- |
| 系统接入说明 | 系统用途、沙箱地址、版本、接口协议、网络白名单、维护窗口 |
| 接口文档 | 请求/响应样例、分页、筛选、增量游标、限流、超时、错误码、事件订阅或回调 |
| 认证材料 | 测试账号的权限范围、认证流程、Token 生命周期、凭据托管引用；不把密码贴进文档 |
| 数据字典 | 表/对象/字段名、中文含义、类型、必填、单位、精度、枚举、时区、主键与外键 |
| 脱敏样例 | 正常、空值、重复、停用、删除、乱序、跨组织等情况，以及预期查询结果 |
| 业务关系 | 组织与人员、订单与物料、批次与检验、库存与仓库等关系的业务解释 |
| 数据治理规则 | 来源可信度、数据分级、允许访问的组织/角色、保留时间与更新频率 |
| 写入契约（后续需要） | 草稿/审批状态、幂等键、版本锁、撤回、冲销、补偿、回执与对账办法 |

优先拿到 OA 的身份/组织数据，以及一个业务系统的只读接口。先选择一个可核对的场景，例如“检验异常影响哪些批次、库存和订单”，不要同时铺开所有系统。

## 2. 语义层建模需要的材料

- 对象清单：业务名称、系统编码、唯一标识、归属系统与数据分级。
- 关系清单：关系方向、关联字段、一对一/一对多、有效时间和无匹配记录的处理方式。
- 业务口径：同名异义、同义异名、状态枚举、数量与金额的计算方式。
- 校验样例：给出几条已知数据，说明应提取出什么对象、关系和证据。
- 发布边界：什么是可编辑草稿，什么变更需要复核，如何判断新版本影响已有查询。

使用现有 [模拟数据字典](../reference/exports/元域智语-测试数据字典-v1.0.docx) 可以先熟悉操作，但正式映射必须依据企业实际字典。

## 3. 开发环境和工具

| 类别 | 需要准备 |
| --- | --- |
| 代码 | 可访问的 Git 仓库、分支/合并规则、代码评审入口；提交约定见 [GitHub 提交与交付](GITHUB_DELIVERY.md) |
| 本地运行 | 与项目兼容的 Node/npm、Python 虚拟环境；Electron 开发环境；启动方式见 [开发指南](GETTING_STARTED.md) |
| 接口调试 | HTTP 调试工具、可复用请求集合、脱敏响应样例、统一错误码记录 |
| 数据与模型 | 测试数据库连接、只读查看工具、本地或内网模型地址、精确模型 ID/版本、资源配额 |
| 凭据与网络 | 测试网/VPN/白名单、证书链、团队批准的凭据托管方式 |
| 质量验证 | 现有自动化测试、契约测试、测试数据、缺陷复现步骤与日志查询入口 |
| 集成环境 | 与生产隔离的沙箱；联调使用独立租户/账号，能重置模拟业务状态并保留证据 |

不要为了“清理工程”删除正在使用的虚拟环境、模型目录、数据库或客户端运行目录。

## 4. 团队协作需要统一的入口

- 一个需求与缺陷看板：记录场景、验收结果、复现步骤和关联代码变更。
- 一个代码评审入口：通过合并请求跟踪变更，接口和文档随代码一起更新。
- 一个文档入口：本项目统一为 `docs/README.md`，外部协作平台可以链接这里，不再维护另一份过期副本。
- 一个沟通渠道：用于联调安排和故障通知，结论回填工单或文档，不只留在聊天记录。
- 一个测试结果存放位置：保存环境、版本、输入、预期、实际结果和证据；凭据、个人信息与原始业务记录按企业规则隔离。

## 5. 可以开始首轮联调的判断

同一个场景已具备可用沙箱、认证方式、字段字典、脱敏样例、权限范围与预期结果，即可开始连接器开发。若缺少其中任何一项，先补材料或继续契约/Mock 测试，不用猜测字段和业务含义代替真实设计。
