# 元域智脑能力验收与优化项目清单

版本：v1.2  
日期：2026-09-07  
适用范围：桌面端智脑、Agent 服务、模型网关、企业系统连接层

## 一、验收结论

当前版本已经具备“受控 Agent”的基础骨架：模型网关支持结构化答复协议；对话、运行记录和证据链按租户、用户、会话和设备隔离；读取与写入工具均经服务端授权；高风险写入必须经过一次性本人确认和审批。协议通过不表示本地模型已在线或回答质量已验收，当前真实模型与桌面验收限制见 [改进记录第三、四批](AGENT_RUNTIME_IMPROVEMENT_2026-09-06.md)。

但不能把现状描述为完整的企业智能体：

| 能力 | 当前结论 | 进入真实开发前的缺口 |
| --- | --- | --- |
| 智能对话 | 可用，已支持同任务承接、跨任务长期目标、用户主动固定和实体线索记忆 | 缺少流式过程状态和以真实语料构建的对话质量评测 |
| 多模态语义理解 | 已完成受控开发基线 | 已支持 PDF、DOCX、XLSX 的有界文本提取和服务端 OCR 适配器；仍需企业病毒扫描、DLP、版面解析和视觉模型联调 |
| 企业数据访问与业务处理 | 安全链路可用，数据源仍为状态化模拟 Connector | OA、MES、ERP、WMS、QMS 等真实 Connector、字段级策略、数据契约和联调尚未落地 |

本项目的目标不是让模型直接“操作系统”，而是在可追溯证据、最小权限和确认审批边界内，让用户用自然语言完成查询、分析、方案和受控任务发起。

## 三、优化项目

### P0：多模态受控理解通道

目标：让用户上传图片、扫描件、PDF 后，智脑能理解材料内容，但未经内容安全检测的材料绝不进入模型、检索或写入规划。

建设内容：

1. 增加受限文件存储、哈希、保留期和访问审计；附件不再只保留在本次内存请求中。
2. 接入反病毒与文件类型深度检测；PDF 在隔离进程中渲染和解析，拒绝加密、畸形或含脚本的文件。
3. 建设 OCR、表格提取、版面分析和图片理解适配器，输出统一的 `DocumentEvidence`：页码、坐标、原文片段、置信度、分类级别和来源哈希。
4. 对抽取文本做内容级提示词注入检测、敏感信息识别和脱敏；只有 `modelContentEligible=true` 的证据片段可进入模型。
5. 模型回答必须引用附件页码/区域和置信度；低置信度内容只能提示人工复核，不可用于写入动作。

验收标准：上传一份含表格的 PDF 和一张检验图片，智脑能提取关键字段、标注证据位置；嵌入“忽略规则”等文本的材料被隔离；任何附件证据都不能绕过权限或直接触发写入。

当前 OCR 适配器配置：服务端设置 `MULTIMODAL_OCR_ENDPOINT` 与可选的 `MULTIMODAL_OCR_API_KEY`。端点默认只能是企业内网地址，接收 `attachmentId`、`mimeType`、`contentBase64`，返回 `{ text, confidence?, region? }`。返回文本依然会接受内容安全检测；未配置、超时或不可用时，图片材料不进入模型。

### P0：真实系统连接与数据权限闭环

目标：将现有模拟 Connector 替换为可灰度启用的真实连接层，并保证每次数据访问均可解释、可审计、可撤销。

建设内容：

1. 建立 Connector 标准：认证方式、健康检查、数据契约、限流、重试、幂等、超时、字段映射和错误码。
2. 优先接入 OA/BPM、ERP、MES、WMS、QMS；先只读查询，再草稿写入，最后审批后正式写入。
3. 在 Connector 前执行组织、数据域、对象、行级、字段级和数据分级策略；禁止由前端或模型传入任意查询条件扩大范围。
4. 以短时、用途绑定的服务凭据访问下游系统；凭据不返回客户端、不进入模型上下文或日志。
5. 为每个 Connector 建立数据新鲜度、可用性和降级策略。Connector 不可用时，答复必须明确“未读取到实时数据”，不能用历史结果冒充当前事实。

验收标准：不同角色访问同一业务对象得到不同字段和范围；撤销角色权限后，已有会话不能继续读取；下游异常时只返回可追溯的降级结果；每条证据可追溯到系统、对象、字段版本和查询时间。

当前 Connector 适配器配置：服务端使用 `ENTERPRISE_CONNECTORS_CONFIG_JSON` 定义系统端点，例如 `{"erp":{"endpoint":"http://erp-gateway.local","tokenEnv":"ERP_CONNECTOR_TOKEN"}}`。智脑仅向端点发送服务端推导的系统标识、业务标识、结构化查询条件和身份范围，不转发用户原始自然语言。生产记录必须包含稳定编号、租户、组织、版本、分级和发生时间；可引用正文通过 `statement` 等既有字段返回。历史响应另需覆盖声明及有效区间，详见接入指南。凭据缺失或端点不可用时明确降级，不将模拟记录表述为实时数据。

工作台只展示 Connector 的配置就绪态，不会因为页面刷新主动探测下游系统：`本地模拟` 表示没有真实系统配置；`已配置，待受控验证` 表示端点与服务端凭据已通过本地配置校验，首次有权限的业务查询才会进行实际调用；`配置待处理` 表示端点或凭据不合规。只有一次受控查询成功返回后，回答才会引用“企业接入数据”。

### P0：意图、动作与任务状态机

目标：杜绝“分析完成”被显示为“申请已完成”，并让自然语言请求在查询、分析、建议、草稿、确认、审批、执行之间保持明确边界。

建设内容：

1. 将任务拆分为 `conversation`、`read`、`analysis`、`proposal`、`confirmation`、`approval`、`execution`、`receipt` 八类状态。
2. 用结构化意图契约替代单纯关键词：对象、动作、范围、时间、证据需求、是否涉及写入。低置信度时先追问，不查询和不生成命令。
3. 模型只输出计划和受控参数候选；服务端根据工具 Schema、授权和核心对象状态二次校验后才创建命令。
4. 增加“取消待确认动作”和后台过期回收；未确认命令不得以任何形式显示为已完成。
5. 前端固定展示当前状态、数据读取范围、待确认动作和执行回执，避免用泛化的“任务完成”覆盖真实业务状态。

验收标准：输入“采购”“帮我看看这个”“分析一下告警”均不会创建写入命令；只有包含明确动作且通过授权的请求才出现确认卡；确认前没有下游写入，确认后仍必须有审批和回执才能显示为完成。

### P1：智能对话与任务协作体验

目标：让智脑表现为能持续理解、能澄清、能展示处理进展的企业 Agent，而不是一次性问答框。

建设内容：

1. 建立会话摘要、用户目标、业务实体和已确认事实四类记忆；模型答复不得反向写入事实记忆，事实只来自受控证据。
2. 增加流式事件：理解中、读取系统、证据核验、生成建议、等待确认、审批回执。只展示可验证阶段，不展示模型内部思维链。
3. 引入澄清策略：对象、时间范围、组织范围、写入意图不明确时，优先给出一到两个最小追问。
4. 为常见任务建立可复用技能：风险分析、采购协同、质量调查、客户投诉、预算核验。
5. 形成对话评测集，覆盖承接上下文、歧义、越权、错误事实、拒绝与恢复等场景。

验收标准：连续三轮围绕同一告警的对话不串入采购或其他任务事实；智脑能说明“我读取了什么、没有读取什么、下一步需要谁确认”；模型不可把建议、草稿或审批计划说成已执行。

### P1：模型运行与质量治理

目标：提升本地模型在企业任务中的稳定性，同时让所有模型输出受统一安全与质量约束。

建设内容：

1. 固化模型能力基线：中文对话、结构化输出、工具选择、长上下文、视觉理解分别评测，按任务选择模型而非单一模型覆盖全部能力。
2. 模型网关支持健康探测、超时、熔断、并发控制、版本灰度和回退；本地模型不可用时保留确定性安全答复。
3. 对输出增加事实一致性、引用完整性、动作声明和敏感信息检测；不合格输出回退到已验证事实。
4. 建立离线评测与线上抽样复核，持续统计幻觉率、无效追问率、工具误选率、越权拦截率与确认前写入率。

验收标准：每次发布前必须通过对话、工具、权限、多模态和回归场景；高风险动作误触发率为零；所有上线模型版本均可追溯。

## 四、实施顺序

| 阶段 | 交付重点 | 放行条件 |
| --- | --- | --- |
| 第一阶段 | 任务状态机、取消/过期、意图澄清、前端状态重构 | 不再出现“分析完成=申请完成” |
| 第二阶段 | 多模态安全解析、OCR/版面/图片证据、引用展示 | 材料理解可用且未经扫描内容不出域 |
| 第三阶段 | OA/BPM、ERP、MES、WMS、QMS 只读 Connector 与权限策略 | 真实数据访问按对象和字段范围生效 |
| 第四阶段 | 草稿写入、审批回执、流式协作和评测治理 | 端到端业务闭环可审计、可回放、可撤销 |

## 五、上线门槛

1. 所有业务写入均需服务端策略校验、一次性本人确认和业务审批；模型不得拥有直连写权限。
2. 附件原文、个人信息、凭据和跨组织数据不得未经审批离开企业边界。
3. 每个结论必须能列出证据来源、读取时间、适用范围和权限依据；没有证据时明确说明“不确定”。
4. 每次发布均运行对话、多模态、Connector、权限、确认与审计回归集；关键安全用例必须全量通过。
