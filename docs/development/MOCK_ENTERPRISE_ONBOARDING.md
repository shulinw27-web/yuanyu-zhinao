## 在界面使用

1. 使用已授权账号登录元域智营端，打开“企业接入”。创建和保存需要 `meta_model.draft.save`，读取需要 `page.world.view`。
2. 选择场景、输入项目名称，点击“建立空白项目”。企业名称只是描述，不能改变登录身份的租户归属。
3. 查看五类材料的缺项原因。在“登记 / 替换材料”选择类别，读取 UTF-8 的 JSON/TXT 文件，或粘贴正文。
4. 文件读入编辑区后，点击保存才提交。格式错误的材料可以保存以便修订，但会明确显示问题，不计入准备完成。
5. 材料齐备后仍是“待人工复核”。在“模拟连接与数据预览”保持“正常响应”，点击“测试模拟连接”。成功后查看系统、记录数、分页数和字段预览，切换对象核对不同系统的数据。
6. 可选择限流、超时、响应格式损坏、租户不匹配、分页不完整、字段结构变化六种故障，再手动测试。故障应明确失败且不提供部分预览；恢复“正常响应”后重新测试。
7. 替换任何一类材料都会作废旧连接结果与预览。重新验证后才能继续查看；本页没有自动建模、采纳或发布动作。

其他页面的语义上下文加载失败不应挡住该接入页面。403 会显示权限错误；409 表示项目已被更新，需刷新当前版本再提交，编辑内容保留。切换项目、离开页面时，迟到响应不应覆盖新选择。

### 支持的结构与限制

数据字典是 `{tables:[...]}`。每表需提供 `name`、`system`、`primaryKey` 和 `fields`，字段需提供 `name`、`type`。当前类型支持 string、number、integer、boolean；`reference` 指向目标表名，`referenceField` 如存在必须指向目标主键。表名/字段名限定为字母开头的字母、数字、下划线。

样本是 `{records:[{objectType,payload}]}`；对象、主键、必填字段、类型与外键应匹配字典，并且每表至少一条样本。当前按唯一主键快照校验，重复投递会列为待修订，尚未实现事件流去重和增量同步。样本中的 tenantId 只是材料内容，不授予访问权，也不构成未来数据归属校验通过的证明。

### 模拟连接实际验证什么

每次连接测试在服务端创建独立、短生命周期的 `127.0.0.1` HTTP 数据源，通过随机端口和临时认证读取固定合成数据，结束后关闭并撤销测试端口许可。上传的 URL、凭据、API 文本不能指定目的地址；不会读取真实 ERP、WeKnora 或模型接口。

模拟源与上传样本共享仓库中的合成案例来源，但接口响应独立读取固定 fixture，不回显用户修改后的样本。验证的是传输、结构和权限约束，不是独立业务答案准确性。它使用 `mock-onboarding-query.v1`，不是已有真实连接器 `ontology-query.v1` 的适配验收。

| 场景 | 正常读取 | 系统 |
| --- | --- | --- |
| 订单履约 | 18 类对象、34 条记录、3 页 | ERP / MES / OA / OMS / QMS / WMS |
| 批次异常 | 24 类对象、77 条记录、5 页 | ERP / LIMS / MES / OA / OMS / QMS / WMS |

每页最多 16 条、64 KiB，单请求 1 秒、整轮 5 秒超时；本进程最多并发 4 轮，不自动重试。校验请求指纹、快照、覆盖总数、连续游标、重复标识和记录租户；再以当前上传字典检查来源系统、字段、类型、主外键。六类故障均拒绝整批结果，包括已成功读取一页后才超时或出现跨租户记录的情况。

成功仅保存每对象前 10 行预览和连接摘要，不保存完整源信封。连接结果绑定材料修订号；每次测试推进项目修订号，材料内容不变则材料修订号不变。已有页面只读权限可看本人同角色的有效预览，启动测试仍需 `meta_model.draft.save`。网络读取前后重新核对 IAM 权限版本；迟到结果不能覆盖并行材料修订。

接口：`POST /api/semantic-operations/onboarding/:id/connection` 仅接受 `expectedRevision` 与固定 `faultMode`；`GET /:id/preview?objectType=...` 默认选首对象。故障演练结果为 HTTP 200 加 `connection.status=failed`，不是连接成功；版本冲突/无有效预览为 409，非归属项目为 404。暂无任意对象过滤、真实凭据生命周期、通用字段重命名/多跳映射与增量同步。

## 人工业务对齐：本批后端能力

连接检查只回答“读到的数据是否完整、结构是否符合字典”。业务对齐另行检查运营人员明确配置的标识、单位和状态规则。两者状态独立：连接成功时，对齐仍可能 `needs_review`。不会把未配置对象算作已完成，也不会安装预制世界模型。

当前入口是已认证 API 与 SDK，页面只显示对齐阶段摘要，尚无可视化映射编辑器。示例配置单独导出为 `alignment.manual.json`；它是人工编写的输入，不是 Agent 自动生成结果，也不是标准答案文件。

| 规则 | 当前支持 | 拒绝或保留未知 |
| --- | --- | --- |
| 标识与粒度 | 明确统一类型、粒度、源主键；显式一一对应别名；统一 ID 包含租户及保留类型的标识；在配置对象之间解析字典已声明外键 | 不按名称相似度合并；不同粒度合并、同对象标识碰撞、未列出的别名、悬空链接进入问题清单 |
| 单位 | kg/g 标准换算；相同单位保持原值；箱转件通过字典外键逐条查询包装系数；支持逐行单位字段 | 不支持全局固定箱规；缺少或重复包装记录、非正整数系数、未映射单位、重量转件数、跨货币换算不接受 |
| 状态 | 显式源值到目标术语映射，保留源值及“人工映射、非执行回执”标记 | 空值和未配置状态不自动当成正常；已知 `approved` 不允许直接映射为 executed/completed/已执行/已完成 |

规则依据 `evidence` 是运营人员提供的说明，当前没有对说明自动核实或做文档引用认证。任意企业自定义状态的实际含义仍需人工核验；映射结果不授予权限，也不驱动业务执行。换算使用有限、安全范围内的 JavaScript 数值，不支持金融精度、汇率或金额舍入计算。

### 操作顺序与 API

1. 建立项目并登记有效字典；为需要验证的对象准备规则，而不是默认所有对象已对齐。
2. `GET /api/semantic-operations/onboarding/:id/alignment` 读取本人当前角色的配置与报告。
3. `POST` 同一地址，提交 `{expectedRevision, config}`。`config` 版本为 `mock-alignment.v1`，含 `identities`、`units`、`states` 三个数组；至少一条规则，每类最多 40 条，总配置不超过 64 KiB。各规则必须有 `evidence`。
4. 保存映射会递增项目修订，并清除旧连接、预览和对齐报告，但不改变材料修订号。只有配置保存成功，不表示数据验证通过。
5. 再执行 `/connection` 正常读取。后端读取整个有界来源快照，不使用页面前十行作为验证样本；在既有读取前后 IAM 复验及修订竞争检查内产生报告。
6. 再次 GET `/alignment`。`validated_scope` 只表示已配置规则在本次合成快照通过；`needs_review` 表示缺口/冲突。问题时清除全部归一化预览，避免把部分结果当作已接受。成功时每类最多预览十条，另列总计与未配置对象。计数仅表示已处理记录，不能独立证明通过；“配置对象”不等于该对象的全部字段均已对齐。

SDK 方法为 `onboardingAlignment(id)` 和 `saveOnboardingAlignment(id, {expectedRevision, config})`，沿用现有会话，不接受客户端租户或角色授权。读取需页面权限，保存需 `meta_model.draft.save`；项目仍按 tenant/subject/role 隔离。非归属项目 404，旧修订 409，配置结构错误 400，生产环境 403。

示例规则，箱转件通过商品规格查包装系数：

```json
{
  "version": "mock-alignment.v1",
  "identities": [],
  "units": [{
    "objectType": "SalesOrderLine", "field": "qty", "unitField": "unit",
    "sourceUnit": "case", "targetUnit": "piece",
    "lookup": {"objectType": "ItemSKU", "viaField": "sku_id", "valueField": "pieces_per_case"},
    "evidence": "按已核对的商品字典，通过 sku_id 查询每种商品的箱规。"
  }],
  "states": []
}
```

该示例未验证对象标识和状态。若数据存在以 piece 为单位的订单行，还需显式加入 piece→piece 规则；不能直接忽略这些记录。别名配置 `aliases: []` 表示人工明确沿用源主键；非空时要求当前快照每个主键都有明确对应。配置变化、材料变化和连接故障均不会沿用旧报告。当前只有最新配置和版本号，没有完整映射历史或审批签字记录。

- 每主体和角色最多 20 个项目，五类材料各保留当前一份。
- 单份 64 KiB、单项目 256 KiB、同主体角色合计 1 MiB，均按 UTF-8 字节计数。
- 字典最多 40 个表，每表最多 80 字段；样本最多 500 条。
- 三类文字材料至少 24 个非空白字符；这是输入完整度门槛，不是智能语义校验。
- 目前不接受 PDF、Word、图片、音频；既有多模态能力尚未接入本页面。

## 可视化业务对齐操作

元域智营端 → 企业接入 → 选择项目 → **把系统字段对齐为业务含义**。先提交有效的数据字典，编辑器才会显示可选对象和字段。新建项目不预装映射，添加规则也不会调用模型。

1. **对象标识**：选择来源对象，填写统一业务类型和粒度。字典已经声明粒度时必须保持一致。默认沿用源主键；确需改码时逐条添加主键别名，非空别名表必须覆盖当前快照。新建目标别名为文本，源主键按字典类型处理；读取已有数值目标时保留其类型。
2. **计量单位**：选择数值字段、源单位和目标单位。可指定逐行单位字段；未指定时必须有字典单位声明。箱转件必须选字典声明的外键及目标对象的包装数量字段，不能填一个全局猜测倍数。
3. **业务状态**：选择字符串字段，逐项填写源状态和目标含义。遗漏的状态会在全量数据验证时报告，不按前十条预览推断通过。审批状态不能当作执行回执。
4. 每条规则填写人工依据。这里记录的是操作人员的说明，并不核实文档位置、签字或证据真实性。
5. 点击 **保存业务对齐规则**。保存只更新配置，使旧连接与报告失效；随后手动点击 **测试模拟连接**，重新读取完整合成快照。
6. 查看 **业务对齐验证结果**：问题按规则路径、原因和错误码展示；通过时可展开标识、关联、单位、状态结果表，每类最多预览十条。未配置对象单独列出，通过只代表已配置范围，不代表所有字段或完整世界模型。

示例：对象 `SalesOrderLine`，字段 `qty`，源单位 `case`，目标单位 `piece`，逐行单位字段 `unit`，包装关联 `sku_id → ItemSKU`，包装数量字段 `pieces_per_case`。在当前履约合成源中，两条记录分别得到 230 件和 40 件。这只是计量对齐，不会自动过滤取消订单或判断可履约数量。

未保存修改时暂停本页项目切换、材料提交和连接测试，避免操作交错。可以保存，或点击 **放弃修改并重新读取** 明确丢弃本地修改。版本冲突不自动重试；编辑仍显示供核对，重新读取后才能基于最新版本配置。页面关闭、浏览器刷新或离开模块不会持久保存未提交内容，离开前应先保存。

只读角色可查看配置和验证结果，不能新增、修改或提交规则。后端仍执行可信身份与修订校验；界面禁用不是权限边界。`GET /alignment` 返回经校验的字典结构，以及当前身份项目内的需求、接口、字典、规则原文供引用，不返回样本记录。列表与项目详情仍不返回原文。当前没有完整配置历史、跨人协作或证据签核。

### 材料引用：核对“说法来自哪里”

每条规则可选择“绑定材料原文”，展开当前原文，粘贴 12–2000 字符的原样摘录。服务端将引用绑定到材料 SHA-256，拒绝伪造摘录、未知来源、样本记录引用和旧版本。替换材料后，即使旧摘录仍在新文档里，也必须重新选择材料、核对摘录并保存，不能静默沿用旧版本。

API 规则可增加 `materialEvidence: {kind, digest, quote}`。只写人工说明仍可保存和测试，但 `report.materialEvidence.status` 会显示 `needs_review`；全部引用匹配才为 `quotes_verified`。这只证明“原文和版本存在”，不证明摘录支持规则、不证明业务正确，也不是审批或签字。若已绑定引用后来失效，整体映射报告转为 `needs_review`，不再输出对齐预览。

### 从接入项目交给元域智营 Agent

1. 完成五类材料、正常连接测试和已配置映射验证，为每条映射绑定当前材料摘录。
2. 点击 **生成待审阅建模任务**。服务器重新读取完整本地模拟快照，重新校验来源、映射和引用，从当前字典生成候选对象、显式关系及待评审需求条目。这里使用确定性结构提取，不调用云模型，不自动编译计量映射或指标表达式。
3. 项目交接记录、候选提案、Agent 任务在同一事务保存。未改变输入时重复提交复用任务；在途材料或权限变化时拒绝提交。材料缓存按原文内容去重，失败的准备过程可能留有当前身份私有的缓存，但不会留下半个提案或可执行任务。
4. 点击 **转到 Agent 审阅**，进入指定任务。查看来源项目、材料版本、结构检查、样本验证、Diff。任务仍为 `waiting_confirmation`，不会自动签发确认凭证。首次读取租户草稿会初始化基础工作区（可能含平台基础对象），用于计算 Diff，这不等于已采纳候选模型。当前交接为合并模式，采纳会保留既有对象；不是为项目单独创建一个全新模型。
5. 后续采纳继续使用原有确认流程；来源材料、映射配置或连接验证发生变化后，旧提案不能写入草稿，返回 `SEMANTIC_ONBOARDING_SOURCE_STALE`，需要重新验证、交接和审阅。

接口为 `POST /api/semantic-operations/onboarding/:id/handoff`，请求仅含 `expectedRevision`；不接受客户端指定任务、提案、模型或权限。响应返回项目及 `taskId`、`proposalId`、`reused`。交接默认生成整个当前字典的候选结构，未配置映射的对象仍明确列出；没有自动声称这些对象的业务语义已验证。交接任务有持久事件记录和来源信息，目前没有单独的 Agent trace 流，不能将其等同模型执行轨迹。

### 修复原材料缺主键的审阅阻塞

在 Agent 提案中，为原材料缺主键的对象选择原材料已有的字符串或数值字段，然后填写 **主键补充依据**（12–1000 字符）并保存。API 修订体新增 `primaryKeyCorrections: [{objectId, field, reason}]`，审阅人、角色、时间和修订号由服务端记录，不接受客户端伪造。

校验只解除对应对象的缺主键阻断，不删除原始材料和警告，不忽略其他字段、关系或版本冲突。已有明确主键不能通过此入口覆盖；补充字段必须绑定原源字段。之后仍重跑样本和权限检查：无样本不能因结构变绿而直接采纳，有权限且样本通过时也只能采纳到草稿。人工说明不等于生产唯一性已经证明。

## 权限和保存边界

项目使用可信 tenant + subject + role 组合作为存储分区；前端不能通过传 tenantId、角色或其他企业项目编号切换归属。同企业另一用户或另一个角色不会自动共享项目，团队协作尚未实现。

原文和摘要哈希保存于当前项目，列表/详情响应不返回正文。保存需带 expectedRevision，冲突时不覆盖已有材料；计数和字节超限同样不推进版本。当前只有最新正文及递增修订号，不提供完整历史版本恢复或审阅签字记录。

服务在生产环境一律拒绝；租户运行准入只增加新接入前缀的精确 semantic 分类，不开放其他尚未验收的共享业务接口。已有用户库未迁移，在用服务未重启。
