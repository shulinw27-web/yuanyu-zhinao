# 语义建模—智脑消费闭环修复报告

日期：2026-09-10。

## 结论

此前“模型发布成功，但智脑不理解新业务”的断点已补上：经人工校对的模型与读计划发布后，智脑可以解释新术语、沿显式外键读取授权记录、计算缺货和信用指标，并说明实际采用的模型版本。A/B 规则切换影响同一批事实的计算，未发布 C 草稿不影响已发布 B；旧对话也能获得新口径。

这是有边界的可运行实现，不是任意需求输入后自动生成并上线全部业务逻辑。读计划由人工审阅导入；新增对象权限默认关闭；目前单活动工作区、单计划、单根对象。旧失败报告保留在 [修复前联测](SEMANTIC_WORKBENCH_LOOP_EVALUATION.md)，接入步骤见 [配置指南](../guides/PUBLISHED_MODEL_WORKBENCH.md)。

## 2. 测试不是固定答案演示

场景使用 ERP/WMS/OMS/QMS/OA/MES 的 18 对象、22 字段级外键，34 条唯一合成记录和一次重复投递。材料、源事实和独立期望值分别保存。源接口按实际类型及字段过滤，不将独立答案返回给产品。

语义 Agent 收到材料生成候选；确认、采纳、保存、校验、模拟构建、发布均走实际 HTTP。候选未完成业务回放时，发布仍返回 `PUBLICATION_REPLAY_REQUIRED`。随后明确进入人工规则审阅分支，把表达式及正反例交给实际回放器验证，再真实发布到独立 Semantica。不能把这一步说成 LLM 自动编译通过。

智脑的 A/B 盲测不收到材料、公式或答案；只通过发布定义和连接器读实例。一次履约计算实际发出 18 次类型化查询，得到 32 条授权且去重后的关联记录，其余无关记录不会强行加入。

| 验收问题 | 实测结果 |
| --- | --- |
| ORD-X900 有效需求 | 180 件，取消行排除 |
| 南仓自有可用/缺货 | 40 / 140 件，排除寄售、隔离、在途、待检，扣除其他订单预留 |
| 银行确认但未核销 | 7,000 CNY，重复到账不重复加款 |
| 发布 A：曙光额度/信用缺口 | 4,000 / 5,000 CNY |
| 发布 B，同样源事实 | 7,500 / 1,500 CNY |
| B 发布后的原会话追问 | 读取 B，不沿用 A 计算结果 |
| 保存 C 不发布 | 仍采用 B，数值不变 |
| AP-X1 已批准 | 不等于货权转移已执行，需要执行回执 |
| ST-X7 可用量为零 | 不足以证明质量隔离，应查看质量状态 |

另有独立变事实测试：ST-X1 数量由 6 箱改为 8 箱，可用量从 40 变为 60、缺口从 140 变为 120。这证明运行时不是按订单编号返回固定答案。所有分析 `command=null`，没有发货、调拨、核销或权限写入。
