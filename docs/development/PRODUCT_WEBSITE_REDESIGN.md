# 元域产品官网改版方案

日期：2026-09-14。阶段：首批官网改版已实施；客户中心深度改版、完整文档教程体系及正式商业化仍待后续完成。

实施记录：首页、两个独立产品详情、六步合成案例、可展开架构页、方案与交付页已上线本地预览；文档新增独立文章/章节地址、三栏布局和双Agent教程。保留原账务与租户服务。测试和剩余范围见[门户验收](PRODUCT_PORTAL_ACCEPTANCE.md)。下文设计目标不是全部完成声明。

本方案由产品经理审视现有门户，结合官方网站参考形成。覆盖官网、技术文档、客户中心与平台运营，不变更现有企业数据授权和支付规则，不进行公网发布。

## 1. 设计结论

当前网站证明了注册、订单和租户管理可以运行，但没有充分展示“元域到底是什么、产品如何使用、为什么值得接入”。应从商业流程验证页升级为企业产品网站，而非仅增加装饰。

新版定位：**元域——企业 Agent 与语义智能平台。**

对外主张：**连接业务数据，让 AI 理解业务、协同工作。**

解释文案：元域智语将需求、接口和数据字典整理为可校对的业务模型；智脑依据已发布模型和授权数据，提供可追溯的分析与待确认任务。

差异化围绕三件事展开：业务模型可建设、两个 Agent 分工协作、分析与执行有明确边界。不要将“模型聪明”“万能助手”“全自动世界模型”作为无法验证的承诺。

首要转化是让访客看懂并体验产品价值，注册其次，付费在完成方案评估之后。

| 优先级 | 现状 | 对用户的影响 | 改版要求 |
| --- | --- | --- | --- |
| P0 | 首页和产品页使用同一模板 | 点击产品仍看同样内容，缺少深入了解路径 | 首页讲价值，产品详情讲具体工作方式 |
| P0 | 以文字卡片、架构方块为主，没有产品操作证据 | 看不出智脑和元域智语实际长什么样 | 展示真实界面裁切、输入输出及合成案例回放 |

首屏画面不使用宇宙、发光大脑、随机连线或大段代码雨。产品本身是视觉主体。预览图保留足够可读字号，只裁切与当前讲解相关的区域；桌面端和移动端分别选裁切范围。

### 6.2 首页各段落

| 顺序 | 内容任务 | 推荐表现形式 | 点击后的真实目标 |
| --- | --- | --- | --- |
| 1 | 讲清给谁用、解决什么 | 主标题＋可切换产品画面＋两项行动 | 合成演示 / 架构页 |

每段只解决一个问题；不采用八排同规格功能卡片。版式交替使用宽幅产品图、左右分栏、步骤回放、架构图和紧凑资源列表。

### 6.3 完整示例的交互设计

问题：“某原料批次出现质量异常，会影响哪些生产批次、库存和订单？”

1. 查看材料：需求片段、API字段、数据字典；必须为合成或已脱敏资料。
2. 查看候选：原料批次、生产批次、库存、订单及关系；显示候选而非已确认事实。
3. 查看人工校对：主键、关系方向、数量口径；显示校对前后的一个实际差异。
4. 查看发布：模型版本、回放结果、允许业务端使用的范围。
5. 查看智脑回答：点击影响路径能看到来源；事实、假设、建议与未知项分区。
6. 查看下一步：建议保持“待确认”；不伪造发送、冻结、审批完成等回执。

演示采用固定、版本化的安全样本，支持前后步骤和重置。预设回放必须标“示例回放”，不能用打字机动画冒充刚刚发生的真实模型推理。门户不得借用本机默认管理员或私有模型凭据作为公开演示会话。

## 7. 产品详情和技术页

智脑页：一句业务价值 → 工作台全貌 → 连续对话/材料/任务三个具体操作 → 来源与权限 → 支持终端及状态 → 上手教程。

元域智语页：材料准备 → 候选提取 → 可视化校对 → 正反例回放 → 版本发布 → 智脑消费，配真实界面和错误处理例子。

平台架构页：业务入口、Agent协作、语义与知识、系统连接四层；身份、授权、审计贯穿。单独说明产品客户管理与企业执行面之间的生产开通桥接尚未完成。

技术名称在需要解释时出现：Semantica对应建模与语义相关能力，WeKnora对应知识资料与检索；使用具体项目证据解释集成范围，不称为官方合作伙伴。平台架构中的能力位置是概念分层，不强行等同实际服务部署拓扑。

部署页必须说明应用部署位置与模型推理位置是两件事。系统类别不等于现成连接器；未完成真实接入的项目旁直接标记状态，不能藏在页脚免责声明里。

## 8. 文档中心：从说明文字升级为使用工具

桌面采用左目录、中正文、右本页目录；正文建议680–800px。右目录空间不足时先折叠，手机目录使用抽屉。

目录按开始使用、核心概念、智脑、元域智语、知识与异常、集成开发、账号计费、故障排查分组。第一批优先完成这些任务文档：

- 用合成资料走通一次双Agent场景。
- 从数据字典生成对象候选，人工修正主键和关系。
- 回放与发布一个模型，并在智脑中验证它。
- 理解异常的影响路径及证据缺口。
- 创建测试空间、邀请成员、理解未开通状态。
- 创建订单并核对会员、折扣和优惠券。
- 调用门户API：完整请求、响应、错误和权限前提。

文章模板：适用版本/环境 → 前置材料 → 操作步骤 → 预期结果 → 常见失败及处理 → 相关文档。概念文可以短；教程不能只解释名词。

交互要求：文章与章节可复制链接；刷新和返回不丢位置；搜索显示命中片段和无结果提示；代码可复制且有反馈；提供上一页/下一页；页面标题、面包屑和当前目录一致。

公开内容继续只读取受控发布目录，不开放整个内部docs。同步历史文档时先去除私有路径、个人信息、测试账号与内部运维操作。自动API示例不得包含真实密钥。

## 9. 客户中心：先开通和使用，再处理费用

### 9.1 概览与开通

概览优先显示“当前空间、可使用的产品、待完成事项”，而非默认铺满充值、优惠和金额。

目标开通旅程：账号验证 → 企业空间 → 身份与数据授权 → 语义样本验证 → 执行面验收。当前系统只有部分状态，新增阶段只能在相应后端回执接入后标完成；不可前端拼装假进度百分比。

每个未完成项显示阻塞原因、所需材料、下一步和最后更新时间。当前runtimeConnected=false时，展示“生产服务尚未连接”，提供演示/教程入口，不直接放行现有内部智脑。

登录后保留原访问目标与待接受邀请。空状态给一个明确操作，权限不足解释角色，接口失败支持重试；不得用零值代替未知或加载失败。

### 9.2 会员、充值与优惠券

“订阅权益”和“余额账单”分开，付费明确归属当前租户。

订阅页展示当前方案、到期时间、有效权益及续费规则。未对接真实计量的模型用量不显示伪造仪表；展示“未接入计量”。公开方案页暂按体验验证/团队协作/企业接入比较范围，不发布未经确认的新价格。

结算页固定摘要：租户、套餐、周期、原价、折扣来源、优惠金额、实付、支付方式和环境。更换套餐或优惠券后清空旧报价，再由服务端计算；保留明确确认，不因输入券码自动支付。

优惠券显示适用套餐、门槛、期限及不可用原因。会员和券择优不叠加的现有规则保留。订单详情区分待支付、测试支付完成、取消和过期，关联余额流水；退款、发票、真实支付未实现就不提供伪操作按钮。

团队页区分所有者、管理员、成员，调整权限和移除成员有确认；未接邮件服务时继续明确“复制邀请凭证”，不能改成“邮件已发出”。

## 10. 平台运营：专业表格工作区

采用独立后台布局，保留租户、用户、开通、订单、优惠券和审计的关联跳转。列表支持搜索、筛选、状态和更新时间；数据量增加前补齐服务端分页，不只筛选前端局部数据。

详情使用侧栏或详情页展开上下文，重要操作确认目标及影响。停用账号、暂停租户、停用优惠券等继续由服务端校验权限与版本冲突。价格配置、发票、退款等未完成能力不显示可用菜单。

客户中心和平台后台可以同源部署，但必须拥有独立导航与授权边界；视觉拆分不替代服务器鉴权。

## 11. 视觉与交互规格

建议方向：**企业级软件产品展示**。保留元域识别，不延续当前浅绿卡片铺满页面的做法。

| 元素 | 设计建议 |
| --- | --- |
| 主色 | 深墨绿#12312B；强调青绿#147D64；主文字#172A26 |
| 背景 | 白色主阅读区＋少量#F4F7F5灰绿区；深色仅用于重点产品展示 |
| 首页网格 | 12列，最大内容宽1280px；主产品画面允许适度扩展 |
| 字体 | 中文系统无衬线为主；正文16–18px，桌面主标题48–64px，手机32–40px |
| 内容节奏 | 章节间距桌面80–112px、手机40–56px；避免每段标题都采用同一种模板 |
| 控件 | 主次按钮层级明确，主操作通常每个区块一个；主要交互目标至少44px |
| 图形 | 使用自己的产品截图、可点击关系路径、模型差异；不借用他站品牌资产 |
| 动效 | 仅说明状态与步骤，150–250ms为主；尊重减少动画设置，无滚动劫持 |
| 交互反馈 | 加载、无数据、错误、无权限、成功分别设计；状态不能只用颜色表达 |

颜色需按实际前景背景组合复核可读性，以上色值不是已经通过无障碍验收的声明。架构图可作为交互示意，但核心介绍和导航不得依赖动画加载。

依赖外部资源的事项单列：正式运营主体、定价、联系渠道、真实客户授权素材、支付商户、邮箱验证和生产租户桥接。缺失时保留诚实状态；其他页面设计与合成案例可先完成。

## 13. 验收标准与衡量方式

以下是未来验收目标，不是本次已经取得的用户研究或性能结果。

- [ ] 邀请5名未参与项目者阅读首屏和产品段落，至少4名能说清给谁用及双Agent区别。
- [ ] 首页、产品、场景、架构、文档各有独立内容，主按钮均到达对应目标。
- [ ] 每项关键能力附界面、样本或可追溯文档；无虚假客户、认证、SLA、收益数字。
- [ ] 样本回放、真实模型调用与真实业务执行有可见区分；失败和未知状态不冒充成功。
- [ ] 文章/章节深链、刷新、浏览器返回、搜索无结果、代码复制均通过。
