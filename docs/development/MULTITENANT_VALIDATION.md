# 多租户能力全量复测报告

测试日期：2026-09-16。基线：`0fe54be` 加当前工作区改动；不是只对 Git 提交版本测试。环境：Windows、Node.js 24.14.1、本地门户前端、隔离的内存服务与 SQLite 测试库。

**最新进展（2026-09-17）**：完成应用层、独立实例、持久化及备份恢复子项后，新增门户开通申请/取消和部署预检流程。企业身份、权益、撤权及资源激活链路仍未实现。最新实现与边界见第 13 节。**第 1–12 节保留各阶段记录，不代表最新整体状态。**

## 1. 结论

**门户具备已验证的租户管理与资金隔离基础，但整个元域系统尚未达到共享部署的生产多租户标准。**

门户的成员、角色、账单和付款权限测试通过；智脑会话、长期记忆、个人知识资料，以及元域智营提案与快照的身份隔离也通过本轮反例测试。不过，语义建模的实际草稿仍使用全局工作区；门户开通并不会交付对应租户的双 Agent 运行环境。不能用“可以创建多个企业空间”代替“多个企业可以安全共用全部系统”。

本轮登记 **3 个已复现问题、1 个已明确的未实现项**。没有修改业务实现、生产数据或支付配置；新增了可重复执行的测试、就绪探针和本报告。

### 数据与环境隔离

- 服务测试使用 Alice、Bob、Carol 和平台管理员等合成身份，同一用户在不同租户拥有不同角色。
- 智脑与知识专项故意保持 `subjectId`、`sessionId`、`deviceId` 相同，仅改变 `tenantId`，避免只测到用户隔离而漏掉租户隔离。
- 浏览器使用独立账号、甲乙丙三个合成企业：甲公司所有者同时是乙公司普通成员；另一账号仅属于丙公司。
- 浏览器接口通过 Playwright 转发到临时内存服务，保留真实前端、HTTP 校验、登录、CSRF 和服务端业务逻辑。未替换成静态接口返回，未修改正在运行的门户数据库。
- 持久化测试库位于 `output/multitenant-sqlite-*/synthetic.db`；没有访问现有 `backend/.data/product-portal.db`。四个进程共享同一个专用测试库。
- 本轮未进行真实付款、生产企业数据访问或新的付费模型联调；没有使用真实租户去执行破坏性反例。浏览器与临时合成服务测试完成后关闭。

## 4. 问题与未实现项

### MT-GAP-01：实际语义草稿共享，P0

类型：已复现的共享部署隔离问题。

复现使用真实 `handleGovernanceRoutes` 和内存存储，分别传入已认证身份上下文的合成租户 A/B；两者均具备建模权限。它验证的是进入路由后的租户隔离，不是绕过真实登录系统的渗透测试。

1. B 读取初始草稿。
2. A 保存只属于 A 的策略 `SYNTHETIC_A_ONLY_POLICY`。
3. B 再次读取，得到 A 的策略。
4. B 保存 `SYNTHETIC_B_ONLY_POLICY`。
5. A 再次读取，自己的策略已被 B 的策略替换。

原因：`backend/src/services/meta-model-service.js` 使用固定 `oa_meta_model_runtime / workspace` 键；草稿读、存、校验和模拟接口未接收租户参数。`backend/src/routes/governance-routes.js` 的草稿路由也未把 `agentIdentity` 传入服务。提案和快照有身份检查，不能弥补最终落地工作区共享。

影响：如果同一个运行实例允许两个租户进入建模模块，模型元数据会串租户，并存在相互覆盖风险。已发布模型的租户匹配检查不能解决草稿隔离。当前门户没有接通该运行实例，因此这里**不是“公开注册即可读取另一家企业数据”的证明**。

修复验收：以可信租户身份分区草稿、校验、模拟、发布、快照目标及 Semantica 部署；拒绝缺少租户身份的请求；A/B 同时建模、发布、回滚后各自内容保持独立。还需规划旧共享数据迁移，而非只给前端增加租户下拉框。对应现有 Checklist 的 SL-06b 和语义服务租户隔离项。

### MT-GAP-02：共用出口 IP 的租户相互限流，P2

类型：已复现的可用性隔离问题，不是数据泄露。

在独立 HTTP 服务上，B 的一次工作区读取为 200；同 IP 的 A 再发 179 次普通请求后，B 的下一次工作区读取变为 `429 RATE_LIMITED`。

原因：`backend/src/http/product-portal-server.js` 只使用远端 IP 与 auth/general 分类作为限流键，普通接口共用 180 次/分钟额度。匿名目录接口也消耗同一 general 桶。企业共享出口、反向代理配置不当时容易相互影响。

修复验收：保留 IP 层防滥用，同时增加可信会话/主体及必要的租户额度；明确代理信任配置，不能直接信任浏览器可伪造的租户头或转发 IP。分别测试同出口双租户、公网攻击流量及多实例限流。不能简单删除限流。

### MT-GAP-03：门户开通没有交付租户执行环境，P0

类型：原有明确的未实现项，不计作新发现的越权漏洞。

探针完成专业版测试订单付款，再由平台管理员设为 `sandbox_ready`。返回的 `runtimeConnected` 仍为 `false`。

门户和说明文档对此已有明确边界：创建空间、增加成员、购买测试会员，不会自动创建或绑定智脑、元域智营、企业 IAM、连接器、知识库或模型用量额度。因此也没有“门户停用租户后，所有已登录业务端立即撤权”的完整生产链路可供验收。

修复验收：建立可幂等、可补偿的租户开通流程，产生并验证执行面身份、资源及权益绑定；完成开通失败回滚、重复回调、暂停/恢复、成员离职、旧会话和在途任务撤权等双端测试。不能通过把 `runtimeConnected` 改成 `true` 来完成。

### MT-UI-01：切换租户后保留上一租户的成功提示，P2

类型：浏览器已复现的操作上下文问题。

在甲公司创建测试订单，页面显示“订单已生成，请核对应付金额。这是测试订单。”；切换到乙公司后，账单主体正确显示“当前角色没有账单管理权限”，但顶部仍保留甲公司的订单成功提示。

代码依据：`apps/product-portal/src/ProductPortal.vue` 的空间切换仅调用 `clearCheckout()` 并清理邀请凭证，没有清理 `notice` 和 `alert`。这次未观察到越权入账，但旧提示会让用户误判当前租户的操作结果。

修复验收：租户变化时统一清理租户相关提示、选中对象和确认状态；对异步返回绑定原始租户上下文。测试甲创建/失败→乙、甲报价→乙、甲慢请求→切换→响应返回等场景。

先实现并验证语义运行时租户分区（MT-GAP-01），再接门户到执行面的身份、资源和撤权链路（MT-GAP-03）；期间补齐限流公平性（MT-GAP-02）和界面上下文清理（MT-UI-01）。在前两项关闭前，不应让多个企业通过同一个未分区的语义建模运行实例处理真实业务数据。

## 9. 修复实现与回归（2026-09-16）

### 已修复

| 编号 | 修复 | 仍需区分的边界 |
| --- | --- | --- |
| MT-GAP-01 | 认证后绑定租户上下文；草稿、校验/模拟、已发布模型、发布锁与对账状态按租户分区；采纳/回滚多状态事务、旧世界模型模板及后台巡检同步补齐 | 外部 Python Semantica 仍是单租户 Demo 图，非 Demo 请求现在明确拒绝，不代表独立语义实例已交付 |
| MT-GAP-02 | 普通请求按服务端验证的账号分配180次/分钟；匿名流量独立按IP限制180次/分钟 | 保留每IP普通流量1200次/分钟的粗粒度防滥用上限；注册/登录仍每IP12次/分钟、密码计算并发2。单进程内存限流不是分布式公平调度 |
| MT-UI-01 | 账号、租户、角色、空间状态变化时同步清空提示、报价、订单确认、邀请凭证、优惠券和支付确认；迟到响应重新比较视图范围 | 不取消服务端已经成功执行的操作；用户返回原租户后可通过订单记录查看结果 |

租户边界实现位于 `backend/src/services/semantic-tenant-context.js`。AsyncLocalStorage 只绑定服务端认证身份，不使用请求体或可伪造的租户头。不同租户的嵌套调用、提案身份与当前上下文不一致会拒绝。生产环境、启用外部身份配置或关闭 Demo 身份头时，缺少上下文的模型访问拒绝，不回退到 Demo。

旧 `workspace` 数据仅由 `demo-enterprise` 继续使用；新租户从初始模板开始，不自动复制历史企业草稿。本次没有删除、批量迁移或改变现有草稿归属。需要迁移历史内容时应另行审核归属。

Semantica 的发现、校验、发布、发布状态、图同步和重置接口，对非 Demo 租户均返回 `tenant_endpoint_required`、`requestAttempted=false`，不发送共享实例请求。发布编排将此识别为“未尝试”，不会错误进入不确定发布状态。独立实例/服务身份接入前，这是必要的安全限制，而非完整多租户功能。

## 14. 执行面IAM租户隔离（2026-09-17）

### 问题与修复

## 17. 后台编排与巡检租约修复（2026-09-17）

### 已复现的问题与修复

- 编排运行中取消后，旧Worker仍能写入成功检查点并启动下一步骤。检查点与完成回执现绑定每次领取的独立租约标识，同时校验任务状态、Worker及有效期；暂停、取消或重新领取使旧结果失效。
- 租约过期仍能完成任务，同一Worker再次领取后也缺少轮次隔离。现拒绝过期及旧轮次结果，客户端列表不返回租约。单次任务过期在下次扫描记为失败，不自动重放；周期任务保留下一次计划运行。
- 语义巡检只在CLI包装层核验租户权限，其他调用调度服务的入口可能漏检。现将准入、可信租户上下文及结果复验移入调度服务；CLI不再重复检查和扣减额度。准入等待期间取消计划，不启动检查函数。
- 已取消巡检可通过恢复或立即运行再次激活，现改为终态，需要新建计划。过期或被替换的结果不写入巡检记录，也不生成对应发现通知。
- 巡检异常原文直接写入记录和通知，可能携带路径或供应商敏感内容，现改为固定失败标识及安全提示。空结果或缺少必要字段记为失败；编排没有相应检查点也不能宣告成功或等待确认。
