## 3. 实际联调过程

1. WeKnora 解析四份资料；项目通过只读适配器检索、复验原文引用。
2. 两个 Agent 分别回答制度 A/B、审批与执行问题；测试同一知识问答上下文的追问。
3. 生成 Wiki 理解草稿，再测试语义 Agent 接收资料引用和完整结构化附件。首轮 Wiki 失败，未伪造草稿填补，而是使用已明确提供的原材料继续候选建模。
4. 语义 Agent 返回 18 类对象、22 条关系，对象来源、主键和粒度正确；另行检查外键方向与基数正确。此结果由模型规划和确定性结构抽取共同完成，不是纯模型自由生成。
5. 确认采纳到隔离草稿后，直接发布被 409 拒绝。随后使用独立的“模拟人工建模”对照：明确配置读取代数、访问策略、正反例回放，校验后发布到真实 Semantica，并独立读取发布回执核验版本与指纹。
6. 智脑使用发布模型读取 Mock 业务事实；知识联合核验同时回读 WeKnora 引用和业务结果。普通聊天另测连续追问，并在第二组显式开启模型解释。
7. 注入查询覆盖缺失、同主键库存冲突、外租户记录、过期模型指纹及未绑定身份，检查拒绝结果与连接器查询次数。

重要区别：候选草稿没有自动生成可执行读取方案；人工对照不是 Agent 自动建模验收。Wiki 重试成功后，没有重新执行完整 Wiki → 候选 → 人工校对 → 发布链。联合核验接口本身不调用模型，带模型的业务解释是独立聊天路径；主聊天没有因此获得自动 WeKnora 补查能力。

### 业务理解与上下文

发布模型后，九项计算全部与独立预期一致。开启解释后的追问能承接 ORD-T900，指出寄售审批记录虽为 approved，但 execution_receipt_id 为空；调拨单 in_transit 且 received_qty 为 0，不能计入南仓可用。模型提出补核回执、签收和核销链路的建议，没有生成业务执行命令。

解释首轮用时 35.394 秒，追问 20.830 秒，每轮 18 个关联查询步骤。联合只读核验为 325 毫秒、36 次连接器查询（两次读取用于一致性核验）。均为本机单次观测，不是生产性能指标。未开启解释的对照轮只返回可信事实与计算，不能据此宣称自然语言解释已验收。

关键词四次初始检索约 47–237 毫秒；混合四次约 903–1,153 毫秒。混合检索相对更慢，但本轮找回了关键词遗漏的规则。未测高并发或广泛召回率。

### 权限与错误分支

- 覆盖缺失、库存主键冲突和外租户记录返回 409，不返回业务计算结果。
- 过期模型选择返回 409，业务连接器查询为 0。
- 未绑定的质量身份返回 403，不返回知识引用。
- 未审定草稿发布被拒绝；成功发布来自显式人工配置并通过正反例回放的对照模型。

| 编号 | 优先级 | 证据与影响 | 建议修复 / 验收方向 |
| --- | --- | --- | --- |
| DM-01 | P1 | 业务知识追问首轮 503 `KNOWLEDGE_MODEL_UNAVAILABLE`，同输入重试 200 | 增加不泄露内容的阶段诊断，区分超时、上游、响应解析；有限重试后保留明确失败。现有证据不足以断言欠费或网络故障 |

| DM-03 | P1 | 关键词 `execution_receipt_id` 的前五条均为字典片段，漏掉需求中的审批规则；混合对照召回且模型答对 | 优化混合召回、文档多样性和片段预算，加入“字段定义＋业务规则”共同覆盖回归；不要把扩大 topK 当作已验证修复 |

| DM-05 | P2 | 语义规划加入未要求的 LIMS，并重复询问已提供的对象/制度信息；实际候选结构未出现多余系统 | 规划绑定材料清单，区分已知、冲突与缺失；测试计划与实际访问范围一致，避免无意义追问 |
| DM-06 | P2 | 可执行读取方案来自人工对照，不是候选 Agent 自动产物 | 后续开发受约束方案提案、预览与回放闭环；继续保留人工审定和发布门禁。这是能力边界，不是本轮发现的计算错误 |
