# 后台编排与语义巡检执行边界

更新：2026-09-17。适用 `agent-orchestration-worker` 与 `semantic-inspection-worker`，不是全部后台服务的统一验收结论。

## 领取与回执

每次领取生成独立随机租约标识，绑定 Worker ID、领取时间及过期时间。记录检查点或提交完成结果，必须同时满足：

- 任务仍允许执行，未暂停或取消；
- Worker ID和本轮租约标识一致；
- 租约尚未过期。

同一 Worker 重启或再次领取，不可使用上一轮租约写结果。客户端列表不返回租约标识。暂停、取消都会作废租约；正在等待外部服务返回的调用可能继续，但迟到结果不能推进后续步骤。已经发出的请求不能据此撤回。

## 智脑编排

每个步骤先检查租户运行准入，恢复该租户IAM和语义上下文；在准入等待结束后核对租约，再启动步骤。步骤返回后复验授权，检查点写入再核对租约。

只有全部步骤具有成功检查点，编排才能标为成功；等待确认也必须有对应检查点，不能仅因执行函数返回就称为完成。提案仍需本人确认，调度器不自动发起业务写入。

运行中的单次任务现在可以暂停。恢复是用户显式重启一轮执行，会重新领取并清空本轮检查点，不是从任意中间位置精确续跑。已经发生的只读请求可能重复，不保证外部调用恰好一次。

单次任务租约过期后，下次扫描记为失败，不自动重跑可能已经发出的动作。周期任务将过期一轮记为失败，下一计划时间仍可开始新一轮。当前没有租约自动续期；长步骤超过租约应视作失败，不能放宽回执校验掩盖超时。

## 语义巡检

租户运行准入已放在 `runSemanticInspectionCycle` 内，CLI或其他内部调用共享相同检查；CLI不再重复扣减每日额度。登记沙箱一次成功准入累计一次额度，执行失败不退额。权限或IAM版本在执行期间变化时，结果不会作为成功巡检保存。

取消为终态，不能通过“恢复”或“立即运行”重新启动；需要建立新计划。被取消、过期或替换的租约提交结果时，不写入本次结果，也不生成对应发现通知。

执行器必须返回 `severity: info|warning`、非空摘要和检查项数组。空返回、缺少字段或未知严重度记为失败，不能显示“全部通过”。上游异常原文不会写进巡检记录或通知，只保存固定失败标识并提示核查授权与服务，防止路径、凭据或供应商内容泄漏。

## 升级现有 Worker

1. 停止接收新的调度轮次，等待在途执行结束，停止旧 Worker。
2. 更新后端服务与两个 Worker，避免旧、新版本混跑。
3. 旧租约没有新标识，不能提交新版本回执。让其过期后检查任务状态：单次编排失败后人工重新建任务；巡检可在有效计划下重新领取。
4. 先用合成租户验证取消、暂停、过期和授权拒绝，再恢复日常调度。

本次开发没有替用户重启在用服务或修改真实任务。

## 验收边界

专项回归覆盖取消时仍在执行、租约到期、同Worker新旧轮次、单次任务过期清理、暂停恢复、无检查点虚报成功、巡检空结果、上游错误脱敏、权限检查期间取消及撤权前后结果拒收。见[多租户测试报告第17节](../development/MULTITENANT_VALIDATION.md#17-后台编排与巡检租约修复2026-09-17)。

尚未覆盖全部领域事件、通知外发和其他Worker的生产租户授权；全量调度扫描的公平性、通知与巡检状态原子提交、分布式长租约续期、多节点故障演练也未在本轮交付。登记沙箱仍不开放后台业务Agent和共享业务连接器，不能据此解除生产门禁。
